# Data representation: text, sound, images and compression

- **Compression:** why it is used; **lossy** and **lossless**; **run-length encoding (RLE)**.

## Notes

### Text: character sets

A **character set** is the list of characters a computer can recognise, each with its own binary code.

| | ASCII | Unicode |
|---|---|---|
| Bits per character | 7 bits (extended ASCII uses 8) | Up to 16 or 32 bits (e.g. UTF-8, UTF-16, UTF-32) |
| Characters | 128 (extended: 256) | Over 140,000, covering almost every language, symbols and emojis |
| Used for | English letters, digits, punctuation | Any language and symbol |
| File size | Smaller | Larger, since each character needs more bits |

- ASCII codes are in order: 'A' = 65, 'B' = 66 ... 'a' = 97 ... '0' = 48. So if you know 'A' is 65, 'D' is 68.
- **Unicode** was created because ASCII does not have enough characters for languages such as Chinese, Arabic or Hindi. The first 128 Unicode characters are the same as ASCII.

### Sound

Sound is an **analogue** wave. To store it, a computer measures ("samples") the height of the wave at regular intervals and stores each measurement as a binary number.

- **Sample rate:** the number of samples taken per second, in hertz (Hz). 44,100 Hz = 44,100 samples per second.
- **Sample resolution (bit depth):** the number of bits used to store each sample.

| Increase... | Quality | File size |
|---|---|---|
| Sample rate | Better: closer to the original wave, higher frequencies captured | Larger |
| Sample resolution | Better: each sample more accurate | Larger |

**Sound file size (bits) = sample rate × sample resolution × length (seconds)**

Example: 8,000 Hz, 8 bits, 10 seconds = 8,000 × 8 × 10 = 640,000 bits = 80,000 bytes = 78.125 KiB.

### Images

An image is a grid of **pixels** (picture elements). Each pixel is stored as a binary number for its colour.

- **Resolution:** the number of pixels in the image, usually width × height (e.g. 1024 × 768). More pixels = sharper image but larger file.
- **Colour depth:** the number of bits used per pixel. n bits give 2ⁿ colours: 1 bit = 2 colours, 2 bits = 4, 8 bits = 256, 24 bits = about 16.7 million. Higher colour depth = more colours and larger file.
- **Metadata:** data about the image stored in the file, such as width, height, colour depth, date, camera. The computer needs this to rebuild the image.

**Image file size (bits) = width × height × colour depth**

Example: 1024 × 768 pixels at 8 bits per pixel = 786,432 pixels × 8 = 6,291,456 bits = 786,432 bytes = 768 KiB.

### Units of data (Cambridge uses the binary units)

| Unit | Size |
|---|---|
| 1 nibble | 4 bits |
| 1 byte | 8 bits |
| 1 kibibyte (KiB) | 1024 bytes |
| 1 mebibyte (MiB) | 1024 KiB |
| 1 gibibyte (GiB) | 1024 MiB |
| 1 tebibyte (TiB) | 1024 GiB |
| 1 pebibyte (PiB) | 1024 TiB |

**Converting:** bits → bytes: ÷ 8. Bytes → KiB: ÷ 1024. Going up a unit, divide by 1024; going down, multiply by 1024. For example 3 MiB = 3 × 1024 = 3072 KiB.

### Compression

**Compression** makes a file smaller. Reasons: it takes **less storage space**, it **uploads/downloads faster** and uses **less bandwidth**, and streaming works with less buffering.

| | Lossless | Lossy |
|---|---|---|
| What happens | The file is made smaller with **no data lost**; the original can be rebuilt exactly | Some data is **permanently removed** |
| Quality | Original quality kept | Reduced quality |
| File size reduction | Smaller reduction | Bigger reduction |
| Use when | Exact data needed: text, program files, some images (e.g. PNG) | Small loss acceptable: photos (JPEG), music (MP3), video (MP4) |

- **Lossy ideas:** reduce the **resolution** or **colour depth** of an image; reduce the **sample rate** or **sample resolution** of sound; remove sounds humans cannot easily hear.
- **Run-length encoding (RLE)** is lossless. It replaces a run of repeated data with **one value and a count**.

Text: AAAABBBCCD → 4A 3B 2C 1D (10 characters become 4 pairs). RLE works well when there are long runs (e.g. a flag, a logo) and badly when data changes all the time (it can even make the file bigger).

## Key terms and definitions

- **Character set** — all the characters and symbols that a computer system can recognise, each with its own code.
- **ASCII** — a character set using 7 bits per character (128 characters) for English letters, numbers and symbols.
- **Unicode** — a character set using more bits per character so that it can represent characters from all languages and many symbols.
- **Sample rate** — the number of samples of a sound wave taken each second.
- **Sample resolution** — the number of bits used to store each sound sample.
- **Pixel** — the smallest element of an image; a single coloured dot.
- **Resolution (image)** — the number of pixels in an image, given as width × height.
- **Colour depth** — the number of bits used to represent the colour of each pixel.
- **Metadata** — data that describes a file (e.g. width, height and colour depth of an image).
- **Compression** — reducing the size of a file.
- **Lossless compression** — compression in which the original file can be rebuilt exactly because no data is lost.
- **Lossy compression** — compression in which some data is permanently removed, so the original cannot be rebuilt.
- **Run-length encoding (RLE)** — a lossless method that stores repeated data as a value and the number of times it repeats.

## Worked examples

**1. A black and white image is 200 pixels wide and 100 pixels high, with a colour depth of 4 bits. Calculate the file size in bytes. [3]**

Pixels = 200 × 100 = 20,000 [1]. Bits = 20,000 × 4 = 80,000 [1]. Bytes = 80,000 ÷ 8 = **10,000 bytes** [1] (= 9.77 KiB).

**2. Describe how a sound wave is stored in a computer. [3]**

The amplitude (height) of the wave is measured (sampled) at regular time intervals [1]. Each sample is stored as a binary number [1]. The number of samples per second is the sample rate, and the number of bits per sample is the sample resolution [1].

**3. A sound file is changed to use a higher sample rate. State two effects. [2]**

The sound is a more accurate/better quality copy of the original [1]. The file size is larger [1].

**4. Compress this row of pixels with RLE: WWWWWWBBWWW. State whether it is lossy or lossless. [2]**

6W 2B 3W [1]. It is **lossless** because the original can be rebuilt exactly [1].

## Common mistakes

- Saying ASCII "has 7 characters" or that Unicode is "better quality". It is about **number of characters** and **bits per character**.
- Using 1000 instead of 1024 for the conversions between units.
- Forgetting to divide by 8 to change bits into bytes.
- Mixing up **resolution** (pixels) and **colour depth** (bits per pixel).
- Suggesting lossy compression for text or program files. They must be rebuilt exactly, so use lossless.
- Writing "the file is smaller so it is better quality". Compression does not improve quality.
- Describing a sample as "a recording of the whole sound". It is one measurement at one moment.

## Practice questions

1. In ASCII, 'A' has the code 65 and 'a' has the code 97. State the ASCII code for (a) 'F' and (b) 'c'. [2]
2. State two differences between ASCII and Unicode. [2]
3. An image is 1024 pixels wide and 768 pixels high, with a colour depth of 8 bits. Calculate the file size in KiB. [3]
4. How many different colours can be shown with a colour depth of (a) 4 bits, (b) 16 bits? [2]
5. A sound is recorded for 10 seconds with a sample rate of 8,000 Hz and a sample resolution of 8 bits. Calculate the file size in KiB. [3]
6. Convert (a) 2048 KiB to MiB, (b) 3 MiB to KiB, (c) 5,120 bytes to KiB. [3]
7. Explain the difference between lossy and lossless compression and give one file type for which each is suitable. [4]
8. Show the run-length encoding of AAAAABBBBCCCCCCD. How many characters are saved? [3]

<details><summary>Answers</summary>

1. (a) 'F' = 65 + 5 = **70**. (b) 'c' = 97 + 2 = **99**.
2. Any two: ASCII uses 7 (or 8) bits per character, Unicode uses 16/32; ASCII has 128 characters, Unicode has over 140,000; ASCII is mainly English, Unicode supports all languages and emoji; Unicode files are larger.
3. 1024 × 768 = 786,432 pixels × 8 bits = 6,291,456 bits ÷ 8 = 786,432 bytes ÷ 1024 = **768 KiB**.
4. (a) 2⁴ = **16**. (b) 2¹⁶ = **65,536**.
5. 8,000 × 8 × 10 = 640,000 bits ÷ 8 = 80,000 bytes ÷ 1024 = **78.125 KiB** (≈ 78.1).
6. (a) 2048 ÷ 1024 = **2 MiB**. (b) 3 × 1024 = **3072 KiB**. (c) 5120 ÷ 1024 = **5 KiB**.
7. Lossless: no data is lost, the original file can be rebuilt exactly; suitable for text documents or program files (PNG images also acceptable). Lossy: some data is permanently removed to give a much smaller file; the original cannot be rebuilt; suitable for photos (JPEG), music (MP3) or video.
8. **5A 4B 6C 1D**. 16 characters become 8 (4 pairs), so 8 characters are saved (or the data is half the size).
