## Notes

### Searching

Searching means finding whether a value is in a list, and where.

#### Linear search

Check each item in turn, starting from the first, until you find the target or reach the end.

- Works on **any** list (sorted or unsorted).
- Simple, but slow for long lists: in the worst case you check **every** item.
- Best case: the target is the first item (1 check).

```python
def linear_search(data, target):
    for i in range(len(data)):
        if data[i] == target:
            return i          # found: return the index
    return -1                 # not found

print(linear_search([7, 3, 9, 4], 9))   # 2
print(linear_search([7, 3, 9, 4], 5))   # -1
```

#### Binary search

Only works on a list that is **already sorted**. Repeatedly look at the **middle** item and throw away the half that cannot contain the target.

1. Set `low` to the first index and `high` to the last index.
2. Find the middle: `mid = (low + high) DIV 2` (round down).
3. If `data[mid]` equals the target: found, stop.
4. If the target is **bigger** than `data[mid]`, search the upper half: `low = mid + 1`.
5. If the target is **smaller**, search the lower half: `high = mid - 1`.
6. If `low` becomes greater than `high`, the target is not in the list.

```python
def binary_search(data, target):
    low = 0
    high = len(data) - 1
    while low <= high:
        mid = (low + high) // 2
        if data[mid] == target:
            return mid
        elif data[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

data = [3, 8, 12, 15, 21, 27, 34, 40]
print(binary_search(data, 27))   # 5
print(binary_search(data, 10))   # -1
```

**Trace: find 27 in [3, 8, 12, 15, 21, 27, 34, 40]** (indices 0 to 7)

| Step | low | high | mid | data[mid] | Decision |
|---|---|---|---|---|---|
| 1 | 0 | 7 | 3 | 15 | 27 > 15, so low = 4 |
| 2 | 4 | 7 | 5 | 27 | found at index 5 |

Only 2 items checked. A linear search would have checked 6.

Binary search halves the search area each time, so even a list of 1000 items needs at most about 10 checks. Its weakness: the list must be sorted first.

| | Linear search | Binary search |
|---|---|---|
| Data must be sorted? | No | **Yes** |
| Speed on long lists | slow (may check every item) | fast (halves each time) |
| Complexity of the code | very simple | a little more complex |
| Best when | list is short or unsorted | list is long and sorted |

### Sorting

#### Bubble sort

Compare each pair of **neighbouring** items and **swap** them if they are in the wrong order. Repeat passes through the list until a whole pass has **no swaps**. After each pass the largest unsorted item has "bubbled" to the end, so the end part is already in place.

**Sort [5, 3, 8, 1, 4] into ascending order:**

| Pass | List at end of pass | Swaps made |
|---|---|---|
| Start | 5 3 8 1 4 | |
| 1 | 3 5 1 4 **8** | 5↔3, 8↔1, 8↔4 (3 swaps) |
| 2 | 3 1 4 **5 8** | 5↔1, 5↔4 (2 swaps) |
| 3 | 1 3 4 5 8 | 3↔1 (1 swap) |
| 4 | 1 3 4 5 8 | none, so the list is sorted and the algorithm stops |

```python
def bubble_sort(data):
    n = len(data)
    swapped = True
    while swapped:                       # stop when a pass has no swaps
        swapped = False
        for i in range(n - 1):
            if data[i] > data[i + 1]:
                data[i], data[i + 1] = data[i + 1], data[i]   # swap
                swapped = True
        n = n - 1                        # the last item is now in place
    return data

print(bubble_sort([5, 3, 8, 1, 4]))      # [1, 3, 4, 5, 8]
```

Pseudocode version of the swap, which needs a temporary variable because you cannot overwrite a value you still need:

```
SET Temp TO List[i]
SET List[i] TO List[i + 1]
SET List[i + 1] TO Temp
```

Points to remember:
- The **flag** (`swapped`) lets the algorithm stop early; without it, the algorithm does unnecessary passes.
- Easy to write, but **inefficient** on long lists (many comparisons).
- For a list of n items, a full pass makes n − 1 comparisons.

#### Merge sort

A **divide and conquer** algorithm in two phases.

1. **Divide**: keep splitting the list in half until every sub-list has **one item** (a list of one item is already sorted).
2. **Merge**: repeatedly merge pairs of sub-lists into a bigger sorted list. To merge, compare the **first items** of the two lists, take the smaller, and repeat until both lists are empty.

**Sort [38, 27, 43, 3, 9, 82, 10]:**

```
Divide:
[38 27 43 3 9 82 10]
[38 27 43 3]        [9 82 10]
[38 27] [43 3]      [9] [82 10]
[38] [27] [43] [3]  [9] [82] [10]

Merge:
[27 38] [3 43]      [9] [10 82]
[3 27 38 43]        [9 10 82]
[3 9 10 27 38 43 82]
```

Merging [3, 27, 38, 43] and [9, 10, 82]: compare 3 and 9, take 3; compare 27 and 9, take 9; compare 27 and 10, take 10; compare 27 and 82, take 27; and so on.

```python
def merge(left, right):
    result = []
    i = 0
    j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result = result + left[i:] + right[j:]   # add what is left over
    return result

def merge_sort(data):
    if len(data) <= 1:
        return data
    mid = len(data) // 2
    return merge(merge_sort(data[:mid]), merge_sort(data[mid:]))

print(merge_sort([38, 27, 43, 3, 9, 82, 10]))
# [3, 9, 10, 27, 38, 43, 82]
```

You do not need to memorise the Python for merge sort (it uses a function that calls itself); you must be able to **describe** it and **show the stages** on a small list.

| | Bubble sort | Merge sort |
|---|---|---|
| Idea | swap neighbours that are out of order | split, then merge sorted halves |
| Speed on long lists | slow | much faster |
| Extra memory | none (sorts in place) | needs extra lists |
| Code | short and simple | longer, uses recursion |
| Best for | short lists, or lists that are nearly sorted | long lists |

### Choosing an algorithm

- Is the list **sorted**? If yes, binary search is best. If not, use linear search, or sort it first if you will search many times.
- How **long** is the list? For short lists, simple algorithms are fine.
- Is **memory** limited? Bubble sort needs no extra memory; merge sort does.
- To **evaluate** algorithms: compare the number of steps/comparisons, whether they give correct results, and how easy they are to write and maintain.

## Key terms and definitions

- **Linear search**: checks each item in a list in turn until the target is found or the end of the list is reached.
- **Binary search**: repeatedly halves a sorted list by comparing the target with the middle item, discarding the half that cannot contain it.
- **Bubble sort**: repeatedly compares adjacent items and swaps them if they are in the wrong order, until no swaps are needed.
- **Merge sort**: divides a list into single-item lists, then repeatedly merges them back together in sorted order.
- **Pass**: one complete run through the list in a sort.
- **Swap**: exchanging the positions of two items (needs a temporary variable).
- **Sorted list**: a list in which the items are in order, e.g. ascending or descending.

## Worked examples

**1. Explain why a binary search cannot be used on the list [9, 2, 14, 6]. [2]**

Binary search works by comparing the target with the middle item and discarding half the list (1). This only works if the list is sorted; in an unsorted list the target could be in either half, so a half might be discarded wrongly (1).

**2. Show the list after each pass of a bubble sort (ascending) for [6, 2, 9, 4]. [3]**

Pass 1: compare 6,2 → swap: 2 6 9 4; compare 6,9 → no swap; compare 9,4 → swap: **2 6 4 9**.
Pass 2: 2,6 no swap; 6,4 swap: **2 4 6 9**; 6,9 no swap.
Pass 3: no swaps, so the list is sorted: **2 4 6 9**.
Marks: pass 1 correct (1), pass 2 correct (1), final pass with no swaps shows the algorithm stops (1).

**3. Describe how a merge sort works. [4]**

Split the list in half (1), and keep splitting each half until every sub-list has one item (1). Merge pairs of sub-lists, comparing the first item of each and taking the smaller each time (1), until one sorted list remains (1).

**4. A sorted list has 16 items. State the maximum number of items a binary search checks, and compare it with a linear search. [2]**

Binary search: at most 5 checks (16 → 8 → 4 → 2 → 1, and the last item) (1). Linear search: could check all 16 (1). (Accept "about 4 or 5".)

## Common mistakes

- Using binary search on an **unsorted** list.
- Taking the middle wrongly. With 8 items (indices 0–7), `(0 + 7) DIV 2 = 3`, not 4. Always round **down** unless the question says otherwise.
- Binary search: setting `low = mid` instead of `mid + 1` (never-ending loop).
- Bubble sort: showing the whole sort in one go. The question usually asks for the list **after each pass**; do the pass fully, left to right, before writing it down.
- Stopping bubble sort as soon as the list *looks* sorted. You need a pass with **no swaps** to know.
- Saying merge sort "sorts the halves separately and joins them". Merging means **comparing** the first items and picking the smaller.
- Describing the algorithms vaguely ("it goes through the list"). Name the comparison and the action.
