# Data transmission and error detection

> **In the exam:** Paper 1 Computer Systems (1 h 45 min, 75 marks). This topic is worth about 8–12 marks. Common questions: describe packet switching [4], the contents of a packet header [3], serial vs parallel or simplex/half/full duplex [2–4], advantages of USB [2], "describe how parity / checksum / ARQ detects errors" [3–4], "explain why a parity check may miss an error" [2], and symmetric vs asymmetric encryption [3–4].

## What you need to know

- A **packet** has a **header** (destination address, packet number, originator's address), a **payload** and a trailer.
- **Packet switching:** how data is split, sent by different routes and reassembled.
- **Serial** and **parallel** transmission; **simplex, half-duplex and full-duplex**.
- **USB** (Universal Serial Bus): benefits and drawbacks.
- Why errors happen in transmission and how they are **detected**: **parity check** (byte and block), **checksum**, **echo check**, **check digit**, **ARQ** (acknowledgement and timeout).
- **Encryption:** plaintext, ciphertext, symmetric and asymmetric (public and private keys).

## Notes

### Packets and packet switching

Data sent over a network is split into small units called **packets**. Each packet has three parts:

| Part | Contents |
|---|---|
| **Header** | Destination address, **packet number**, originator's (sender's) address |
| **Payload** | The actual data being sent |
| **Trailer** | Marks the end of the packet and may carry error-checking data |

**Packet switching, step by step:**
1. The message is split into packets.
2. Each packet is given a header with the destination address, its packet number and the sender's address.
3. Each packet travels **independently**, and may take a **different route**. A **router** reads the destination address and picks the best next route at that moment.
4. Packets can arrive **out of order**. The receiving computer uses the **packet numbers** to put them back in order.
5. If a packet is missing or corrupt, the receiver asks for it to be sent again. When all have arrived, the message is reassembled.

Why it is good: the whole message does not stop if one route is busy or broken; network capacity is used efficiently.

### Serial and parallel transmission

| | Serial | Parallel |
|---|---|---|
| How | Bits sent **one at a time** down a single wire | Several bits (e.g. 8) sent **at the same time** down several wires |
| Over long distance | Reliable: fewer errors, no skew | Bits may arrive out of sync (**skewing**) and wires interfere (crosstalk) |
| Speed | Can be very fast with modern technology | Faster only over very short distances |
| Cost | Cheaper cable | More expensive cable |
| Use | USB, Ethernet, long distances | Inside a computer (e.g. between the CPU and memory) |

### Direction of data

- **Simplex:** data goes in **one direction only** (e.g. a computer to a printer, a TV remote).
- **Half-duplex:** data goes in **both directions, but not at the same time** (e.g. a walkie-talkie).
- **Full-duplex:** data goes in **both directions at the same time** (e.g. a phone call, broadband).

### USB (Universal Serial Bus)

USB sends data **serially**. 

**Benefits:** a standard connector for many devices; the plug is designed so it cannot be inserted the wrong way round (older connectors only); devices are **detected automatically** and drivers installed; can **power** devices; backward compatible with older versions; fairly fast; error checking is built in.
**Drawbacks:** limited cable length; slower than some other connection types for very large data; only a limited number of devices can connect to one port without a hub.

### Errors in transmission

Data can be **corrupted** (changed or lost) by interference, electrical noise, problems on the line, or packet loss. Errors are **detected**; the usual fix is to **resend**.

### Parity checks

Sender and receiver agree on **even parity** or **odd parity**. One bit (the **parity bit**) is added to each byte so that the total number of 1s is even (even parity) or odd (odd parity).

- Data 1011001 has four 1s. Even parity: parity bit **0** → 01011001. Odd parity: parity bit **1** → 11011001.
- The receiver counts the 1s in each byte. If the count is not what was agreed, an **error** has occurred and the data is rejected or resent.

**Limitations:** it cannot say **which bit** is wrong; and **two bits changed** (so the parity stays the same) is **not detected**.

**Parity block (parity byte):** a group of bytes is sent. Each byte has a parity bit (rows), and an extra **parity byte** is sent with a parity bit for each column. The receiver checks all rows and columns. One wrong row and one wrong column **locate the exact bit**, which can be corrected.

### Checksum

The sender uses an **algorithm** to calculate a value from the data (the **checksum**) and sends it with the data. The receiver calculates it again from the data received. If the two values are **different**, an error has occurred and the data is resent.

### Echo check

The receiver sends a copy of the received data **back to the sender**. The sender compares it with the original. If they differ, an error occurred. **Weakness:** if they differ you do not know whether the error was on the way there or on the way back, and it doubles the traffic.

### Check digit

A **check digit** is the last digit of a code (e.g. ISBN on a book, barcode number). It is calculated from the other digits by an algorithm. When the code is **typed in or scanned**, the computer recalculates it and compares. It catches **data entry errors**: a wrong digit, **transposed** digits (e.g. 45 typed as 54) or a missing/extra digit.

### ARQ (Automatic Repeat reQuest)

ARQ uses acknowledgements and a timeout:
1. The sender sends data (with an error check).
2. The receiver checks it. If there are no errors it sends a **positive acknowledgement**. If errors, a **negative acknowledgement**.
3. If the sender gets a **negative acknowledgement**, or **no acknowledgement before the timeout** expires, it **resends** the data.
4. This repeats until a positive acknowledgement arrives or a set **number of attempts** is reached.

### Encryption

**Encryption** scrambles data so that it is meaningless to anyone who intercepts it. **Plaintext** (the original data) is put through an **encryption algorithm** with a **key** to produce **ciphertext**. The ciphertext is decrypted back to plaintext with the correct key. Encryption does not stop data being intercepted; it stops it being **understood**.

| | Symmetric | Asymmetric |
|---|---|---|
| Keys | **One** key to encrypt and decrypt | **Two** keys: a **public** key (shared with everyone) and a **private** key (kept secret) |
| How | Sender and receiver both need the same key | Data encrypted with the receiver's public key can only be decrypted with their private key |
| Weakness | The key must be sent to the receiver, so it could be **intercepted** | Slower to process |

## Key terms and definitions

- **Packet** — a small unit of data sent across a network, made of a header, payload and trailer.
- **Packet switching** — a method of data transmission in which a message is split into packets that may travel by different routes and are reassembled at the destination.
- **Serial transmission** — data sent one bit at a time over a single wire.
- **Parallel transmission** — data sent several bits at a time over several wires.
- **Simplex** — data transmission in one direction only.
- **Half-duplex** — data transmission in both directions, but not at the same time.
- **Full-duplex** — data transmission in both directions at the same time.
- **Parity bit** — an extra bit added to data so that the number of 1s is always even (or always odd).
- **Checksum** — a value calculated from the data by an algorithm and sent with it so the receiver can check for errors.
- **Check digit** — a digit added to the end of a number, calculated from the other digits, to detect data entry errors.
- **ARQ** — a method of error correction using acknowledgements and timeouts to resend data that has errors.
- **Encryption** — scrambling data into ciphertext so it cannot be understood if intercepted.
- **Symmetric encryption** — encryption that uses the same key to encrypt and decrypt.
- **Asymmetric encryption** — encryption that uses a public key to encrypt and a private key to decrypt.

## Worked examples

**1. Describe how packet switching is used to send a file across a network. [4]**

The file is split into packets [1]. Each packet has a header containing destination address, packet number and sender's address [1]. Each packet may take a different route, chosen by routers [1]. At the destination the packets are put back in order using the packet numbers and reassembled [1].

**2. Even parity is used. The byte 10110110 is received. Has an error occurred? Explain. [2]**

The byte has five 1s, which is an odd number [1], so with even parity an error has occurred [1].

**3. Describe how ARQ ensures data is received correctly. [4]**

The receiver checks the data for errors [1]. If correct, it sends a positive acknowledgement [1]. If errors found, it sends a negative acknowledgement and the sender resends [1]. If no acknowledgement arrives within the timeout, the sender resends [1]. (This repeats until acknowledged or a set number of tries.)

**4. A parity check does not find an error even though two bits changed. Explain why. [2]**

Two bits changing keep the number of 1s even/odd as before [1], so the parity looks correct and the error is not detected [1].

## Common mistakes

- Saying the header "contains the data". The data is in the **payload**.
- Forgetting the **packet number** in the header, or saying the packets "arrive in order".
- Mixing up half-duplex and full-duplex ("both directions" is not enough: say whether it is **at the same time**).
- Saying parity "corrects" errors. It only **detects** them (and ARQ re-sends).
- Saying a parity bit "makes the data 100% safe". Two flipped bits get past it.
- Describing the checksum as "the sum of the data". It is the result of an **algorithm**, calculated at both ends and compared.
- Confusing a check digit (typing/scanning errors) with a checksum (transmission errors).
- Saying encryption "stops hackers getting the data". It makes stolen data **unreadable**.
- Saying serial is slower "because bits are sent one at a time". Over long distance serial is reliable and often faster.
