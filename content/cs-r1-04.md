## Notes

### The CPU and Von Neumann architecture

The **CPU** (central processing unit) processes instructions. In the **Von Neumann architecture**, both **instructions and data are stored in the same main memory (RAM)** and the CPU fetches and executes instructions one after another.

| Component | Purpose |
|---|---|
| **ALU** (arithmetic logic unit) | Does **calculations** (add, subtract...) and **logic** operations (AND, OR, NOT, comparisons) |
| **Control unit (CU)** | **Decodes** instructions, sends **control signals** to the other parts and controls the flow of data |
| **Registers** | Very small, very fast memory locations inside the CPU |
| **Buses** | Wires that carry data between components |

**Registers you must know:**

| Register | Holds |
|---|---|
| **PC** (program counter) | The **address of the next instruction** to be fetched |
| **MAR** (memory address register) | The **address** of the memory location about to be read from or written to |
| **MDR** (memory data register) | The **data or instruction** that has just been fetched from, or is about to be written to, memory |
| **CIR** (current instruction register) | The **instruction currently being decoded and executed** |
| **ACC** (accumulator) | The **results of calculations** made by the ALU |

**Buses:**
- **Address bus:** carries the **address** of the memory location; one direction only (from the CPU to memory).
- **Data bus:** carries **data and instructions** between the CPU, memory and input/output; both directions.
- **Control bus:** carries **control signals** (e.g. read, write, clock signals) from the control unit to other components, and status signals back.

### The fetch–decode–execute cycle

**Fetch**
1. The address in the **PC** is copied to the **MAR** (using the address bus).
2. The **PC is incremented** (to point to the next instruction).
3. The instruction stored at that address in RAM is copied to the **MDR** (using the data bus; the control unit sends a read signal on the control bus).
4. The instruction is copied from the MDR to the **CIR**.

**Decode**
5. The **control unit decodes** the instruction in the CIR, using the CPU's **instruction set** (the list of all the commands the CPU can carry out).

**Execute**
6. The instruction is **carried out**. For example the ALU does a calculation and the result goes in the ACC, or data is loaded from memory, or a **jump** changes the PC to a new address.

The cycle then repeats. This happens billions of times a second.

### CPU performance

| Factor | What it is | Effect |
|---|---|---|
| **Clock speed** | Number of FDE cycles per second, in Hz (3 GHz = 3 billion per second) | Higher = more instructions per second, so faster. Too high produces **heat** |
| **Number of cores** | Each core is a processing unit that can run its own FDE cycle | More cores = more instructions at the same time. Only helps if the software can use several cores/run tasks in parallel |
| **Cache size** | A small, very fast memory **inside or next to the CPU** that stores frequently used instructions and data | The CPU gets data **faster than from RAM**, so it waits less. Bigger cache = more stored, but cache is expensive |

### Embedded systems

An **embedded system** is a computer system **built into a device** to do **one dedicated task** (as opposed to a general-purpose computer such as a laptop that can run many different programs).

Examples: washing machine, microwave, digital watch, car engine management, traffic lights, central heating thermostat, security alarm, smart TV remote.

Advantages: cheap, small, reliable, low power use. Disadvantages: only one function, usually hard to upgrade or change the program.

### Input devices

| Device | How it works / use |
|---|---|
| **Barcode scanner** | A laser/light beam reflects off the black and white lines; the reflection is read by a sensor and converted to a number, which the computer looks up in a database (price). Used at shop tills |
| **QR code scanner** | A camera captures the square pattern, which stores more data than a barcode (e.g. a website address) and can be read from any angle |
| **Digital camera** | Light passes through a lens onto a sensor; each cell measures light and creates a pixel, stored as digital data |
| **2D scanner** | Light is shone over a paper page and sensors read the reflection to build a digital image |
| **3D scanner** | Captures the shape of an object (lasers, light or cameras measure distances) to build a 3D model, e.g. for 3D printing |
| **Microphone** | Sound waves move a diaphragm, which is converted into an electrical signal and then sampled |
| **Touchscreen** | **Capacitive:** a finger changes the electric field on the screen, and the position is calculated (multi-touch). **Resistive:** pressure presses two layers together and the point of contact is found. **Infra-red:** a finger breaks a grid of infra-red beams |
| **Keyboard, mouse, interactive whiteboard** | Keys/clicks/pen touches converted to signals |

### Sensors

A **sensor** measures a physical quantity and sends the readings to a computer (usually through an **analogue-to-digital converter**). Sensors are used in **automatic systems** (e.g. heating, burglar alarms, greenhouses, car parks, traffic lights).

| Sensor | Measures | Example use |
|---|---|---|
| Temperature | Heat | Central heating, oven, greenhouse |
| Light | Brightness | Automatic street lights, camera flash |
| Pressure | Force/weight | Burglar alarm mat, weather station |
| Moisture | Water in soil/material | Automatic watering |
| Humidity | Water vapour in air | Greenhouse, air conditioning |
| Infra-red | Heat/movement (IR beam) | Motion detector, burglar alarm |
| Proximity | Closeness of an object | Car parking sensor |
| Acoustic | Sound level | Noise/glass-break alarm |
| Gas | Gas concentration | Gas leak, carbon monoxide alarm |
| pH | Acidity | Fish tank, chemical process |
| Level | Height of liquid | Water tank, fuel gauge |
| Flow | Rate of flow | Water pipes, fuel injection |
| Accelerometer | Acceleration/tilt | Phone screen rotation, airbag |
| Magnetic field | Magnetic field | Door/window alarm, car anti-lock braking |

**How a sensor-based system works:** the sensor sends readings to the processor → the processor **compares** the reading with a stored value → if needed it sends a signal to an **actuator** (e.g. heater, motor, valve, buzzer) → the sensor keeps taking readings, **continuously**.

### Output devices

- **LCD/LED screen:** pixels made of tiny light-emitting elements (LED backlight on LCD) change colour to form the image.
- **Projector (DLP/LCD):** the image is made by a small chip or LCD panel and a lamp, and focused by a lens onto a large screen.
- **Speaker:** converts a digital signal to analogue (DAC), which moves a cone to make sound waves.
- **Inkjet printer:** tiny nozzles spray **droplets of ink** onto the paper line by line. Good for photos; low-volume.
- **Laser printer:** a laser draws the page onto a charged **drum**; **toner** (powder) sticks to the charged areas, is transferred to paper and **fused** (melted) by heat. Fast; good for large print runs.
- **3D printer:** builds a solid object **layer by layer** from a digital design, e.g. melted plastic, resin or powder. Used for prototypes, prosthetics, models.
- **Actuator:** a device that **moves or controls something** when it receives a signal from the processor (e.g. motors, valves, heaters, buzzers).

## Key terms and definitions

- **CPU** — the central processing unit: the part of the computer that processes data and instructions.
- **Von Neumann architecture** — a computer design in which instructions and data are stored in the same main memory.
- **Fetch–decode–execute cycle** — the process by which the CPU fetches an instruction from memory, decodes it and carries it out.
- **Program counter (PC)** — the register that stores the address of the next instruction to be fetched.
- **Clock speed** — the number of fetch–decode–execute cycles the CPU can carry out per second.
- **Core** — a processing unit within the CPU that can carry out its own FDE cycle.
- **Cache** — a small, very fast memory in or next to the CPU that stores frequently used instructions and data.
- **Instruction set** — the list of all the machine-code commands that a CPU can process.
- **Embedded system** — a computer system built into a device to carry out a dedicated function.
- **Sensor** — an input device that measures a physical property (e.g. temperature) and sends the data to a computer.
- **Actuator** — an output device that causes a physical movement or change when it receives a signal.

## Worked examples

**1. Describe the fetch stage of the fetch–decode–execute cycle. [4]**

The address in the PC is copied to the MAR [1]. The PC is incremented [1]. The instruction at that address in RAM is copied to the MDR [1]. The instruction is then copied from the MDR to the CIR [1].

**2. A computer has a faster clock speed, more cores and a larger cache. Explain how each could improve performance. [3]**

A faster clock speed means more FDE cycles per second, so more instructions are processed per second [1]. More cores means more instructions can be processed at the same time [1]. A larger cache means more frequently used data is held close to the CPU, so fewer slower trips to RAM [1].

**3. A greenhouse uses a computer to keep the temperature at 20 °C. Describe how a sensor is used. [4]**

The temperature sensor sends readings to the processor continuously [1]. The processor compares each reading with the stored value of 20 °C [1]. If it is too low, the processor sends a signal to an actuator that turns the heater on/opens the vent [1]; if too high it switches the heater off/opens a vent [1].

**4. State what is meant by an embedded system and give one example. [2]**

A computer system built into a device [1] to perform a single/dedicated task, e.g. a washing machine controller [1].

## Common mistakes

- Mixing up MAR (an **address**) and MDR (**data/instruction**).
- Saying the PC "holds the current instruction". It holds the **address of the next** one. The CIR holds the current instruction.
- Forgetting "the PC is incremented" in the fetch stage.
- Saying more cores "always doubles" speed. It depends on the software.
- Saying the **ALU** "controls" things. The **control unit** does; the ALU calculates and does logic.
- Describing a sensor as "it detects temperature and turns on the heater". The **processor** compares and decides; the **actuator** acts.
- Saying a barcode "contains the price". It holds a number; the price is looked up in a database.
- Describing cache as "stored on the hard drive". It is memory on or near the CPU.
