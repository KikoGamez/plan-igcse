## Notes

### Types of software

- **System software** runs and maintains the computer: the **operating system**, **device drivers** and utility programs (e.g. anti-virus, backup, defragmenter).
- **Application software** lets the user do a task: word processor, web browser, games, spreadsheets.

### Operating system functions

The **operating system** manages the computer's hardware and software and provides a platform for applications. Without it you could not use the computer. Examples: Windows, macOS, Linux, Android, iOS.

| Function | What it does |
|---|---|
| **User interface** | Lets the user communicate with the computer (e.g. a graphical user interface or a command line) |
| **Managing files** | Creates, names, moves, copies, deletes and organises files and folders; keeps track of where they are stored |
| **Managing memory** | Decides which program uses which part of RAM, stops programs overwriting each other, and uses virtual memory |
| **Managing peripherals and device drivers** | Controls input/output devices; **drivers** let the OS and a device (e.g. a printer) understand each other |
| **Managing multitasking** | Shares processor time so several programs appear to run at once |
| **Providing security** | Passwords, user accounts, access rights, firewall and malware protection |
| **Managing user accounts** | Different users have separate settings, files and levels of access (e.g. administrator vs standard) |
| **Handling interrupts** | Responds to signals that need attention from the CPU (see below) |

### Interrupts

An **interrupt** is a **signal sent to the processor** by a device or by software to say that something needs **immediate attention**. The processor stops what it is doing, deals with the interrupt, then carries on.

**Hardware interrupts:** a key pressed or mouse clicked; a printer out of paper or finished; a disk transfer finished; power failure.
**Software interrupts:** a program error (e.g. **division by zero**), two programs trying to access the same memory, a program requesting a resource, a stack overflow.

**How an interrupt is handled:**
1. The CPU **checks for interrupts at the end of each fetch–decode–execute cycle**.
2. If there is an interrupt, the CPU checks its **priority**. If it is **higher than the priority of the current task**, the interrupt is handled; if lower, it waits.
3. The CPU **saves the current state** (e.g. the contents of the registers such as the PC) so it can carry on later.
4. The **interrupt service routine (ISR)**, the program written to deal with that interrupt, is run.
5. When the ISR finishes, the CPU **restores the saved state** and **resumes** the interrupted task.

Why use interrupts: the CPU does not waste time constantly checking devices ("polling"); urgent tasks can be dealt with immediately.

### High-level and low-level languages

| | High-level language | Low-level language |
|---|---|---|
| Examples | Python, Java, Visual Basic, C# | **Machine code** (binary), **assembly language** (mnemonics such as LDA, ADD) |
| Readability | Close to **English**, easier to read, write and debug | Hard to read; machine code is just 1s and 0s |
| Portability | **Portable**: runs on different types of computer (after translation) | **Machine dependent**: written for one type of processor |
| Translation | Needs a **compiler or interpreter** | Machine code needs none; assembly needs an **assembler** |
| One statement | Becomes many machine-code instructions | Usually one instruction = one machine instruction |
| Control of hardware | Less direct | **Direct control** of memory, registers and hardware; efficient code |
| Typical use | Most programs, websites, apps | Device drivers, embedded systems, programs needing speed or tiny size |

**Machine code** is the only language the CPU can run directly. All other programs must be translated into it.

### Translators

| Translator | What it does |
|---|---|
| **Compiler** | Translates the **whole** high-level program into machine code in one go (producing an **executable file**), then the program is run |
| **Interpreter** | Translates and **runs one line at a time**; no executable file is produced |
| **Assembler** | Translates **assembly language** into machine code |

| | Compiler | Interpreter |
|---|---|---|
| Speed of running | **Faster**: already translated | Slower: translated every time it runs |
| Errors | Reports **all errors** after attempting to compile the whole program | **Stops at the first error**, so errors are easy to find and fix one by one |
| Source code needed? | No: the executable can be sent out alone (source code kept private) | Yes: the source code and interpreter are needed each time |
| Best for | Finished programs to be released | Developing and testing |

### Integrated development environment (IDE)

An **IDE** is software that helps a programmer **write, test and debug** programs. Common features:
- **Code editor** with **syntax highlighting**, **auto-completion** of keywords/variable names, **auto-correction** and **pretty-print** (neat layout and indentation).
- **Translator** (compiler or interpreter) built in, to run the program.
- **Run-time environment** to run and test the program.
- **Error diagnostics**: shows the line and type of error.
- Debugging tools such as **breakpoints**, stepping through lines, and watching variable values.

## Key terms and definitions

- **Operating system** — system software that manages the computer's hardware and software and provides an interface for the user.
- **Device driver** — software that lets the operating system communicate with and control a hardware device.
- **Interrupt** — a signal sent to the processor by hardware or software requesting its attention.
- **Interrupt service routine (ISR)** — the program that is run to deal with a particular interrupt.
- **High-level language** — a programming language that is close to human language and is independent of the type of computer.
- **Low-level language** — a programming language that is close to machine code and depends on the type of processor.
- **Machine code** — the binary instructions that the CPU can execute directly.
- **Assembly language** — a low-level language that uses mnemonics instead of binary.
- **Compiler** — a translator that converts the whole source code into machine code before it is run.
- **Interpreter** — a translator that translates and executes source code one line at a time.
- **Assembler** — a translator that converts assembly language into machine code.
- **IDE** — integrated development environment: software with tools to write, run, test and debug a program.

## Worked examples

**1. Describe two functions of an operating system. [4]**

Managing files [1]: it creates, names, moves and deletes files and folders and keeps track of where they are stored [1]. Managing memory [1]: it allocates areas of RAM to programs so that they do not overwrite each other [1]. (Other valid: user interface, drivers, multitasking, security, user accounts, interrupts.)

**2. Describe what happens when an interrupt occurs while the CPU is running a program. [4]**

The CPU checks for interrupts at the end of each FDE cycle [1]. If the interrupt has a higher priority than the current task, the CPU saves the current state/register contents [1]. The interrupt service routine is run [1]. The saved state is restored and the original program resumes [1].

**3. Give two differences between a compiler and an interpreter. [2]**

A compiler translates the whole program at once, but an interpreter translates and runs one line at a time [1]. A compiled program runs faster / does not need the compiler to run, but an interpreter is needed every time the program runs [1]. (Or: a compiler reports all errors at the end, an interpreter stops at the first error.)

**4. A company writes software for a washing machine in assembly language. Give one advantage and one disadvantage of using a low-level language. [2]**

Advantage: direct control of the hardware / efficient, small and fast code [1]. Disadvantage: harder to write and debug, and only works on one type of processor [1].

## Common mistakes

- Saying the OS "runs the programs". Be specific: it **manages memory, files, peripherals, security...**
- Writing that an interrupt "stops the computer". The CPU **pauses**, runs the ISR, then **resumes**.
- Forgetting that the **state is saved** (registers/PC) and restored.
- Saying interrupts are checked "all the time". They are checked at the **end of each FDE cycle**.
- Saying an interpreter "translates the whole program". It does it **line by line**.
- Saying a compiler "finds errors one at a time and fixes them". It reports errors after trying to compile the **whole** program; it does not fix them.
- Saying high-level code runs directly on the CPU. It must be **translated** to machine code.
- Describing assembly language as "binary". It uses **mnemonics**; machine code is binary.
