# Data: binary, hexadecimal and arithmetic

> **In the exam:** Mostly Paper 1 (2 hours, 80 marks), usually one or two questions worth about 6–10 marks in total, and the same skills can appear in Paper 2. Typical tasks: convert between binary, denary and hexadecimal (1–2 marks each), add two 8-bit binary numbers and spot overflow (2–3 marks), write a negative number in two's complement (2 marks), do a logical or arithmetic shift and say its effect (2 marks), and explain why hexadecimal is used (1–2 marks). These are calculation marks: show your working and always write all 8 bits.

## What you need to know

- Computers use **binary** to represent all data (numbers, text, sound, graphics) and program instructions.
- Unsigned integers; signed integers using **sign and magnitude** and **two's complement**.
- Convert between binary and denary for whole numbers 0–255.
- Binary arithmetic: **addition**, **logical** and **arithmetic shifts**, and the idea of **overflow**.
- Why **hexadecimal** is used and how to convert between hexadecimal and binary.

## Notes

### Why binary?

A computer is built from billions of tiny switches (transistors) that are either **on or off**. Two states are easy to build, store and detect reliably, so everything is stored as **binary**: 1 (on) and 0 (off). A single binary digit is a **bit**. 4 bits = a **nibble**. 8 bits = a **byte**.

### Binary and denary (base 2 and base 10)

Each column in binary is worth double the one to its right. For 8 bits:

| 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---|---|---|---|---|---|---|

**Binary to denary:** add the column values where there is a 1.
01101101 = 64 + 32 + 8 + 4 + 1 = **109**

**Denary to binary:** go along the columns from 128; if the column fits into what is left, write 1 and subtract, otherwise write 0.
181: 128 fits (53 left), 64 no, 32 fits (21 left), 16 fits (5 left), 8 no, 4 fits (1 left), 2 no, 1 fits → **10110101**.
Check by adding back: 128 + 32 + 16 + 4 + 1 = 181.

- With **n bits** you can store **2ⁿ** different values. 8 bits → 256 values, 0 to 255 (unsigned).
- Always write all 8 bits (leading zeros): 5 is **00000101**, not 101.
- A number is **odd** if its last bit is 1.

### Hexadecimal (base 16)

Hex uses 16 symbols: 0–9 then A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.

**One hex digit = exactly 4 bits** (one nibble). So conversion with binary is easy: split the binary into groups of 4 from the right.

| Binary | Hex | | Binary | Hex |
|---|---|---|---|---|
| 0000 | 0 | | 1000 | 8 |
| 0001 | 1 | | 1001 | 9 |
| 0010 | 2 | | 1010 | A |
| 0011 | 3 | | 1011 | B |
| 0100 | 4 | | 1100 | C |
| 0101 | 5 | | 1101 | D |
| 0110 | 6 | | 1110 | E |
| 0111 | 7 | | 1111 | F |

- 10110101 → 1011 | 0101 → **B5**
- 3C → 0011 | 1100 → **00111100**
- Hex to denary: B5 = 11 × 16 + 5 = **181**. Denary to hex: 200 ÷ 16 = 12 remainder 8 → **C8**.

**Why use hex?** It is **shorter** and **easier for humans to read, remember and copy** than long strings of 1s and 0s, so there are **fewer mistakes**. It converts neatly to binary (4 bits per digit). Used for colour codes (#FF0000), memory addresses, MAC addresses and error codes. (Computers still store everything in binary; hex is for people.)

### Binary addition

Add column by column from the right, with four rules:

| Sum in column | Write | Carry |
|---|---|---|
| 0 + 0 | 0 | 0 |
| 0 + 1 | 1 | 0 |
| 1 + 1 | 0 | 1 |
| 1 + 1 + 1 (with carry) | 1 | 1 |

Example: 00110101 (53) + 00011110 (30)

```
  00110101
+ 00011110
----------
  01010011   = 83
```

Check in denary: 53 + 30 = 83 ✓.

### Overflow

**Overflow** happens when the result of a calculation is **too big to fit** in the number of bits available. In 8-bit unsigned arithmetic the biggest value is 255. If there is a **carry out of the left-hand (most significant) bit**, the answer is wrong.

11001000 (200) + 01111101 (125) = 325, which needs 9 bits: 1 01000101. Only 8 bits can be stored, so the stored answer is **01000101 (69)**, which is wrong. This is overflow.

Effect: an incorrect result, and the program may crash or give errors. Fix: use more bits (e.g. 16).

### Binary shifts

A **shift** moves every bit left or right. Empty places are filled with **0** (logical shift). Bits pushed off the end are lost.

- **Left shift by n**: multiplies by 2ⁿ. 00010110 (22) shifted left 2 → 01011000 (88) = 22 × 4 ✓.
- **Right shift by n**: divides by 2ⁿ (whole-number part; the remainder is lost). 00010110 (22) shifted right 2 → 00000101 (5) = 22 ÷ 4 = 5.5, so 5.
- If a 1 is shifted off the left end of an unsigned number, the answer is wrong (overflow).

**Logical shift:** fills with 0s; treats the bits as just an unsigned pattern.
**Arithmetic shift:** used for **signed** (two's complement) numbers. A left shift is the same, but a **right** shift keeps the **sign bit** (copies the leftmost bit back in), so negative numbers stay negative.

Example: 11110000 is −16 in two's complement.
- Arithmetic right shift by 2 → **11111100** = −4 ✓ (−16 ÷ 4).
- Logical right shift by 2 → 00111100 = 60 ✗ (the sign is destroyed).

### Signed integers

Unsigned integers have no sign (only 0 and positive numbers). To store **negative** numbers we sacrifice the leftmost bit.

**Sign and magnitude:** leftmost bit = sign (0 = positive, 1 = negative); the remaining bits = size.
- 8-bit: 00000101 = +5, 10000101 = −5.
- Range −127 to +127. Problem: **two zeros** (00000000 and 10000000) and awkward arithmetic.

**Two's complement:** the leftmost bit has a **negative** place value: −128, 64, 32, 16, 8, 4, 2, 1.
- Range for 8 bits: **−128 to +127**. Only one zero, and addition works with the same circuit.
- 11111011 = −128 + 64 + 32 + 16 + 8 + 2 + 1 = **−5**.
- 10010110 = −128 + 16 + 4 + 2 = **−106**.

**To write a negative number:** write the positive value in 8 bits, **flip all the bits**, **add 1**.
−45: 45 = 00101101 → flip → 11010010 → +1 → **11010011**.
Check: −128 + 64 + 16 + 2 + 1 = −45 ✓.

**Subtraction** is done by adding the negative: 20 − 13 = 20 + (−13).
00010100 + 11110011 = 1 00000111. Ignore the carry out of the 8th bit → 00000111 = **7** ✓.

| Type | Range (8 bits) | Notes |
|---|---|---|
| Unsigned | 0 to 255 | no negatives |
| Sign and magnitude | −127 to +127 | two zeros |
| Two's complement | −128 to +127 | one zero; easier arithmetic |

## Key terms and definitions

- **Bit:** a single binary digit, 0 or 1.
- **Nibble:** 4 bits.
- **Byte:** 8 bits.
- **Binary:** a base-2 number system using only 0 and 1.
- **Denary:** the base-10 number system (decimal).
- **Hexadecimal:** a base-16 number system using the digits 0–9 and the letters A–F.
- **Unsigned integer:** a whole number with no sign (zero or positive only).
- **Sign and magnitude:** a way of storing signed numbers where the leftmost bit shows the sign and the other bits show the size of the number.
- **Two's complement:** a way of storing signed integers where the leftmost bit has a negative place value.
- **Overflow:** when the result of a calculation is too large to be stored in the available number of bits.
- **Logical shift:** moving the bits left or right and filling the empty places with 0.
- **Arithmetic shift:** a shift on a signed number that keeps the sign bit when shifting right.

## Worked examples

**1. (a) Convert the binary number 10011010 to denary. [1] (b) Convert it to hexadecimal. [2]**

(a) 128 + 16 + 8 + 2 = **154** [1].
(b) Split into nibbles: 1001 | 1010 [1] = **9A** [1].

**2. Add 01101011 and 00101110. Show your working. [2] Explain why 11001000 + 01111101 gives a wrong answer in an 8-bit register. [2]**

First: 01101011 + 00101110 = **10011001** [2] (check: 107 + 46 = 153 = 128 + 16 + 8 + 1 ✓). Award 1 mark for correct method with one error.
Second: the true answer is 325 [1], which is bigger than 255, the largest value 8 bits can hold, so there is a carry out of the left-hand bit and the result is wrong (overflow) [1].

**3. Show −37 in 8-bit two's complement. [2] State the range of numbers that 8-bit two's complement can store. [1]**

37 = 00100101 [1]. Flip: 11011010, add 1: **11011011** [1].
Range: **−128 to +127** [1].

**4. The number 00001101 is shifted left by 3 places. Give the result and describe its effect. [3]**

Result **01101000** [1]. Each left shift multiplies by 2, so three shifts multiply by 2³ = 8 [1]: 13 × 8 = 104 [1].

## Common mistakes

- Writing fewer than 8 bits. Pad with leading zeros: 5 = 00000101.
- Forgetting the carry in binary addition (1 + 1 = 10, not 2).
- Saying hex is "used by computers to store data". It is used by **humans**; computers store binary.
- Two's complement: forgetting to **add 1** after flipping the bits.
- Saying −128 to +128. It is **−128 to +127**.
- Using a logical right shift on a negative number. Use an **arithmetic** shift.
- Writing "a right shift divides by 2" with no mention of the number of places. Say "divides by 2ⁿ" and note that the remainder is lost.
- Converting hex digit by digit in denary. Go through binary (4 bits per hex digit) or use ×16.
