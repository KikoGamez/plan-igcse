## Notes

### Text: ASCII and Unicode

Each character has a **character code**: a number stored in binary. A **character set** is the list of characters a computer can use, with their codes.

- **ASCII** uses 7 bits per character (128 characters: English letters, digits, punctuation, control codes). **Extended ASCII** uses 8 bits (256 characters).
- **Unicode** uses more bits per character (up to 32 bits), so it can store **many more characters**: every alphabet (Spanish ñ, Arabic, Chinese), symbols and emojis. The first 128 Unicode codes are the same as ASCII.
- Disadvantage of Unicode: each character may need **more bits**, so text files are bigger.

Useful ASCII values: **'A' = 65, 'a' = 97, '0' = 48, space = 32**. Letters are in order, so 'D' = 68 and 'e' = 101. Capital and lower-case differ by 32.

**Text file size** = number of characters × bits per character. 2000 characters at 8 bits each = 16 000 bits = 2000 bytes.

### Bitmap images

A **bitmap** image is a grid of tiny squares called **pixels**. Each pixel is stored as a binary number for its colour.

- **Resolution:** the number of pixels (width × height). Higher resolution = more detail, bigger file.
- **Colour depth:** the number of bits used per pixel. Number of colours = **2^colour depth**. 1 bit = 2 colours (black and white), 4 bits = 16 colours, 8 bits = 256 colours, 24 bits = about 16.7 million colours.
- More pixels and more bits per pixel = better quality but a **larger file**.
- A file also stores **metadata** (e.g. width, height, colour depth) so the image can be rebuilt.

**Image file size (bits) = width × height × colour depth.** Divide by 8 for bytes.

Example: 800 × 600 pixels, 24-bit colour.
800 × 600 = 480 000 pixels × 24 = 11 520 000 bits ÷ 8 = **1 440 000 bytes** = 1.44 MB (or about 1.37 MiB).

### Sound

Sound is an **analogue** wave. To store it, the computer measures the height of the wave at regular intervals. This is **sampling**. Each sample is stored as a binary number (**quantised** to the nearest value).

- **Sample rate (sampling frequency):** samples per second, in hertz (Hz). 44 100 Hz = 44 100 samples every second (CD quality).
- **Sample resolution (bit depth):** number of bits per sample. More bits = each sample is more accurate.
- A **higher sample rate** and **bit depth** make the digital sound closer to the original analogue sound, but the **file is bigger**.
- Limitation: because we only have a limited number of bits, each sample is **rounded** to the nearest available value, and what happens between samples is lost. So a digital recording is never a perfect copy.

**Sound file size (bits) = sample rate × bit depth × duration (s) × channels.** (Mono = 1 channel, stereo = 2.)

Example: 44 100 Hz, 16-bit, 60 seconds, mono.
44 100 × 16 = 705 600 bits per second; × 60 = 42 336 000 bits; ÷ 8 = **5 292 000 bytes** (5.292 MB). In stereo it doubles to 10 584 000 bytes.

### Compression

**Compression** makes a file **smaller**. Why? It takes **less storage space**, is **quicker to send** (uses less bandwidth) and **cheaper** to store.

| | Lossless | Lossy |
|---|---|---|
| What happens | file is made smaller with **no data lost**; the original can be rebuilt exactly | some data is **permanently removed** (usually data we are unlikely to notice) |
| Examples | RLE, ZIP, PNG | **JPEG** (images), **MP3** (sound) |
| Used for | text, program files, data where every bit matters | photos, music, video where small loss is acceptable |
| Downside | smaller saving | **quality is lost** and cannot be recovered |

**Run-length encoding (RLE)** is a lossless method. Replace a **run** of repeated values with the **count** and **the value**.
- AAAABBBCC → **4A3B2C**
- WWWWWWBBWWW → **6W2B3W**
- It works well when there are **long runs** (e.g. a cartoon image with big blocks of one colour). If there are **no repeats**, the file can get **bigger**: ABC → 1A1B1C.

### Encryption

**Encryption** scrambles data so that if someone intercepts it they **cannot read it**. It protects **confidentiality** on networks, on stored files and in messages. The original message is the **plaintext**; the scrambled message is the **ciphertext**; the secret used is the **key**. **Decryption** turns ciphertext back into plaintext.

**Caesar cipher (shift cipher):** replace each letter with the one a fixed number of places along the alphabet. The shift is the key. Wrap round from Z to A.
- Shift 3: HELLO → **KHOOR** (H→K, E→H, L→O, L→O, O→R). XYZ → ABC.
- To decrypt, shift the **opposite way**.
- Weak: only 25 possible shifts (easy to try them all), and the letter frequencies still show (the most common letter in English, E, is still the most common).

**Vigenère cipher:** a keyword is repeated along the message; each letter is shifted by the matching key letter (A = 0, B = 1 … Z = 25). The same plaintext letter can become different cipher letters, so it is harder to crack than Caesar.
- Plaintext ATTACK, key KEY (K = 10, E = 4, Y = 24), repeated KEYKEY.
 A+10 = K; T+4 = X; T+24 = R; A+10 = K; C+4 = G; K+24 = I → **KXRKGI**.

**Rail Fence cipher:** write the message in a zigzag across a number of rails (rows), then read off each rail in turn. It **rearranges** letters but does not change them (a transposition).
- 2 rails, MEETME: rail 1 = letters 1, 3, 5 = M, E, M; rail 2 = letters 2, 4, 6 = E, T, E → **MEMETE**.

**Pigpen cipher:** each letter is replaced by a **symbol** (a shape taken from the grid it is in, with or without a dot). A simple substitution, easy to break.

Modern encryption is much stronger than these historic ciphers, which are learnt to show the ideas.

## Key terms and definitions

- **Character set:** the list of characters a computer system can recognise, each with its own binary code.
- **ASCII:** a 7-bit character set that represents 128 characters.
- **Unicode:** a character set that uses more bits per character (up to 32) so it can represent characters from all languages.
- **Pixel:** the smallest element of a bitmap image, with a single colour.
- **Resolution:** the number of pixels in an image (width × height).
- **Colour depth:** the number of bits used to store the colour of each pixel.
- **Sample rate:** the number of sound samples taken per second, measured in hertz.
- **Bit depth (sample resolution):** the number of bits used to store each sound sample.
- **Lossless compression:** compression that reduces file size without losing any data; the original file can be restored exactly.
- **Lossy compression:** compression that reduces file size by permanently removing some data.
- **Run-length encoding (RLE):** a lossless compression method that replaces runs of identical data with a count and a value.
- **Encryption:** converting plaintext into ciphertext so that it cannot be understood if intercepted.
- **Key:** the secret value (such as a shift or a keyword) used to encrypt and decrypt data.

## Worked examples

**1. A bitmap image is 800 pixels wide and 600 pixels high. It uses 24 bits per pixel. Calculate the file size in bytes. [3]**

800 × 600 = 480 000 pixels [1]; × 24 = 11 520 000 bits [1]; ÷ 8 = **1 440 000 bytes** [1].

**2. A sound is recorded at 22 050 Hz with a bit depth of 8 bits for 30 seconds, mono. Calculate the file size in bytes. [3]**

22 050 × 8 × 30 [1] = 5 292 000 bits [1]; ÷ 8 = **661 500 bytes** [1].
(Check: 22 050 samples per second × 1 byte × 30 s = 661 500 ✓.)

**3. (a) Compress the pattern WWWWWWBBWWW using run-length encoding. [2] (b) Give one reason why RLE is not suitable for every file. [1]**

(a) **6W2B3W** [2] (1 mark if counts and letters are right but one run is wrong).
(b) If there are few repeated values, the compressed file can be larger than the original [1].

**4. Explain why a photograph is stored using lossy compression but a text document is stored using lossless compression. [3]**

Lossy removes some data permanently, which makes the file much smaller [1]. In a photo, small losses are unlikely to be noticed [1]. In text, losing any characters would change the meaning, so every bit must be recovered exactly [1].

## Common mistakes

- Using 1000 for KiB/MiB or 1024 for kB/MB. "kibi, mebi, gibi" = 1024; "kilo, mega, giga" = 1000.
- Forgetting to divide by 8 to change bits into bytes.
- Giving a file size with no unit, or in the wrong unit.
- Forgetting the number of channels (stereo = 2) in a sound calculation.
- Saying "colour depth is the number of colours". It is the **number of bits per pixel**; colours = 2^depth.
- Saying lossy compression "removes unnecessary data" without saying it is **permanent** and **cannot be recovered**.
- Applying RLE to the wrong thing: write the **count first**, then the value.
- Caesar cipher: not wrapping round after Z, or shifting the wrong way when decrypting.
- Saying Unicode is better "because it is newer". Say it can represent **more characters** (more languages), at the cost of bigger files.
