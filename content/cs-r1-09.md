## Notes

### Linear search

Check each item **in turn, from the start**, until the item is found or the end of the list is reached. Works on **unsorted** data. Slow for long lists (worst case checks every item).

```
DECLARE Names : ARRAY[1:10] OF STRING
INPUT SearchItem
Found ← FALSE
Index ← 1
WHILE Found = FALSE AND Index <= 10 DO
   IF Names[Index] = SearchItem THEN
      Found ← TRUE
   ELSE
      Index ← Index + 1
   ENDIF
ENDWHILE
IF Found = TRUE THEN
   OUTPUT "Found at position ", Index
ELSE
   OUTPUT "Not found"
ENDIF
```

### Bubble sort

Compare **neighbouring pairs** and **swap them if they are in the wrong order**. After the **first pass** the largest value has "bubbled" to the end. Repeat passes until **no swaps** occur.

Example, sort 5 3 8 1 into ascending order:

| Pass | Steps | Result |
|---|---|---|
| 1 | 5,3 swap → 3 5 8 1; 5,8 no; 8,1 swap | 3 5 1 **8** |
| 2 | 3,5 no; 5,1 swap | 3 1 **5 8** |
| 3 | 3,1 swap | 1 3 5 8 |

```
DECLARE Data : ARRAY[1:5] OF INTEGER
FOR Pass ← 1 TO 4
   FOR J ← 1 TO 5 - Pass
      IF Data[J] > Data[J + 1] THEN
         Temp ← Data[J]
         Data[J] ← Data[J + 1]
         Data[J + 1] ← Temp
      ENDIF
   NEXT J
NEXT Pass
```

Using `Temp` (a **temporary variable**) is essential: without it one value is overwritten. An improved version uses a **flag** (`Swapped ← FALSE` at the start of each pass, `TRUE` when a swap happens) and stops when a pass makes no swaps.

### Standard methods

**Totalling:** `Total ← Total + Value` (initialise `Total ← 0`).
**Counting:** `Count ← Count + 1`.
**Maximum:**

```
Max ← Data[1]
FOR I ← 2 TO 10
   IF Data[I] > Max THEN
      Max ← Data[I]
   ENDIF
NEXT I
```

**Minimum:** same with `<`. Start `Max`/`Min` with the **first value**, not 0 (0 fails for all-negative data and for minimums).
**Average:** `Total / Count`.

### Validation (the data is reasonable) and verification (the data was copied correctly)

| Validation check | What it checks | Example |
|---|---|---|
| **Range** | Value is **between limits** | Month between 1 and 12 |
| **Length** | **Number of characters** is allowed | Password at least 8 characters |
| **Type** | Data is the **right data type** | Age is an integer, not text |
| **Presence** | Data has been **entered** (field not empty) | A surname must be entered |
| **Format** | Data matches a **pattern** | Postcode or date as DD/MM/YYYY |
| **Check digit** | An **extra digit calculated from the other digits** is recalculated on entry; a mismatch means a mistake | The last digit of a barcode/ISBN |

Validation **cannot prove data is correct**: 17 is a valid age in range 0–120 even if the person is 71. Only **verification** helps with that:

- **Visual check:** the user **reads the data on screen** and compares with the original.
- **Double entry:** data is **typed in twice** and the computer compares the two entries (as with a new password).

Validation and verification are **different**: validation checks data is *sensible*; verification checks it was *entered correctly*.

### Test data

Example: a program accepts a **whole-number test mark from 0 to 100**.

| Type | Meaning | Example |
|---|---|---|
| **Normal** | Valid data the program should **accept** | 50 |
| **Extreme** | Valid data at the **very edge** of the allowed range | 0 and 100 |
| **Boundary** | Data at the **edge of acceptable and rejected**: the extreme value and the nearest value outside it | 100 and 101 (also 0 and −1) |
| **Abnormal** (erroneous) | Data that **should be rejected** | −5, 150, "abc", 7.5 |

Test data must come with the **expected result**.

### Trace tables

A **trace table** records **the value of each variable (and output) as you step through the algorithm**, one line per change. Rules: take **one instruction at a time**, write only values that **change**, and use the order of execution. Used to **find the purpose** and to **find logic errors**.

```
N ← 5
Result ← 1
WHILE N > 1 DO
   Result ← Result * N
   N ← N - 1
ENDWHILE
OUTPUT Result
```

| N | Result | OUTPUT |
|---|---|---|
| 5 | 1 | |
| 4 | 5 | |
| 3 | 20 | |
| 2 | 60 | |
| 1 | 120 | |
| | | 120 |

Purpose: calculates 5! (5 factorial).

### Finding and fixing errors

Common faults in given code: **wrong comparison** (`>` instead of `>=`), **missing initialisation**, **loop limit off by one**, **wrong variable**, **missing ENDIF/NEXT**, **condition reversed in REPEAT…UNTIL**. State **the line**, **what is wrong** and **the correction**.

## Key terms and definitions

- **Linear search:** checks each element in turn from the start until the item is found or the list ends.
- **Bubble sort:** compares adjacent items and swaps them if they are in the wrong order, repeating until no swaps are needed.
- **Validation:** an automatic check that data entered is reasonable and meets set rules.
- **Verification:** checking that data has been entered or copied correctly.
- **Check digit:** a digit calculated from the other digits in a number and added at the end, to detect entry errors.
- **Trace table:** a table used to record the values of variables as an algorithm is dry-run.
- **Normal test data:** data that should be accepted.
- **Abnormal test data:** data that should be rejected.
- **Extreme test data:** valid data at the very limit of the range.
- **Boundary test data:** data at the limit of acceptability, the extreme value and the nearest rejected value.

## Common mistakes

- Starting `Max` at 0 or `Min` at 0, instead of the **first value in the list**.
- Describing bubble sort without saying **adjacent items are compared and swapped**, or forgetting that it repeats **passes** until no swaps.
- Swapping with only two assignments (`A ← B` then `B ← A`) and **no temporary variable**.
- Confusing **validation** with **verification** (or saying validation makes sure data is "correct").
- Giving **normal data as extreme** (50 is normal; 0 and 100 are extreme).
- Writing the whole trace table in **one row** or including values that did not change in that step.
- Test data with **no expected result**.
