## Notes

### Input-process-output and computational models

Every computer system takes **input**, **processes** it and produces **output**. A fourth part, **storage**, keeps data and programs.

Example: a digital thermometer. Input: temperature sensor reading. Process: convert reading to °C and compare with limits. Output: number on the display, and a buzzer if too high.

Computational models (ways of organising how a task is done):
- **Sequential:** one instruction at a time, one after another, on one processor.
- **Parallel:** a problem is split into parts that are processed **at the same time** on several processors or cores. Faster for suitable tasks, but harder to program and some tasks cannot be split.
- **Multi-agent:** many independent **agents** (small programs or devices) each make their own decisions and interact, e.g. simulating a crowd, traffic or a swarm of robots.

### Hardware components

| Component | Function |
|---|---|
| **CPU** (central processing unit) | Fetches, decodes and executes instructions; carries out all the processing |
| **Main memory** (RAM) | Holds the programs and data currently in use, so the CPU can access them quickly |
| **Secondary storage** | Long-term storage of programs and data when the power is off (HDD, SSD, optical, cloud) |
| **Input devices** | Send data into the computer (keyboard, mouse, microphone, sensors, scanner) |
| **Output devices** | Present results (monitor, speakers, printer, actuators) |

How they work together: a program is loaded from secondary storage into RAM. The CPU fetches instructions and data from RAM, processes them, and sends results to RAM or to output devices. Input devices supply data.

### The stored program concept and Von Neumann architecture

In the **Von Neumann model**, program instructions and data are **both stored in the same main memory** as binary numbers. The CPU fetches each instruction from memory in turn. The **stored program** idea means you can change what a computer does by loading a different program, instead of rewiring it.

### Parts of the CPU

| Part | Role |
|---|---|
| **Control unit (CU)** | Fetches instructions, **decodes** them, and **sends control signals** to coordinate the other parts of the computer |
| **Arithmetic logic unit (ALU)** | Carries out **arithmetic** (add, subtract) and **logic** (AND, OR, NOT) and comparison operations |
| **Registers** | Very small, very fast storage **inside the CPU** that hold data, addresses or instructions being used right now |
| **Clock** | Sends regular electronic pulses that **synchronise** the CPU's operations; speed is measured in hertz (GHz = billions of cycles per second) |
| **Cache** | Small, fast memory on or close to the CPU, holding recently or frequently used instructions and data |

Common registers (named in many textbooks; know what they do):
- **Program counter (PC):** holds the **address of the next instruction** to fetch.
- **Memory address register (MAR):** holds the **address** in memory being read from or written to.
- **Memory data register (MDR):** holds the **data/instruction** just fetched from memory or about to be written to it.
- **Current instruction register (CIR):** holds the instruction **being decoded and executed**.
- **Accumulator (ACC):** holds results of ALU calculations.

### Buses

A **bus** is a set of wires that carries signals between components.
- **Address bus:** carries the **address** of the memory location to be accessed. One direction only: from CPU to memory.
- **Data bus:** carries the **data and instructions** between CPU, memory and I/O. Two-way.
- **Control bus:** carries **control signals** (e.g. memory read, memory write, clock) and acknowledgements. Two-way.

A wider address bus can address more memory locations; a wider data bus moves more data at once.

### The fetch-decode-execute cycle

The CPU repeats this cycle billions of times a second.

1. **Fetch:** the address in the **PC** is copied to the **MAR**; it is sent along the **address bus**; the instruction at that address is sent back along the **data bus** to the **MDR**, then copied to the **CIR**. The **PC is incremented** to point to the next instruction.
2. **Decode:** the **control unit** works out what the instruction means (what operation, and which data).
3. **Execute:** the instruction is carried out, e.g. the **ALU** does a calculation, data is loaded or stored, or the PC is changed for a jump.

Then the cycle starts again with the next instruction.

### Factors affecting CPU performance

| Factor | Effect |
|---|---|
| **Clock speed** | Higher clock speed = more cycles per second = more instructions processed per second. Limited by heat. |
| **Number of cores** | Each core is a processor that can execute instructions at the same time. More cores = more tasks done **in parallel** (needs software that can use them). |
| **Cache size** | A larger cache stores more frequently used data and instructions, so fewer slow trips to RAM. |
| **Cache type/level** | Level 1 (L1) is the smallest and fastest, inside the core; L2 and L3 are larger and slower. Closer to the CPU = faster. |

Do not say "more cores always makes it twice as fast". It depends on the program and tasks.

### Embedded systems

An **embedded system** is a **computer system built into a larger device** to perform **one dedicated function** (or a few), usually controlled by a program stored in ROM/flash. They usually have no keyboard or screen like a PC.

Examples: washing machine controller, microwave, car engine management and ABS, central heating thermostat, digital watch, traffic lights, smart TV, pacemaker.

Why use them: **small, cheap, low power**, reliable, **work in real time** (respond immediately), suited to one task, and make everyday devices **automatic** and smarter.
Difference from a general-purpose computer (PC): a PC can run many different programs and can be reprogrammed by the user; an embedded system does one job.

## Key terms and definitions

- **CPU:** the component that fetches, decodes and executes program instructions.
- **Control unit:** the part of the CPU that decodes instructions and coordinates the other components using control signals.
- **ALU (arithmetic logic unit):** the part of the CPU that carries out arithmetic and logical operations.
- **Register:** a small, very fast storage location inside the CPU.
- **Clock speed:** the number of cycles the CPU carries out per second, measured in hertz.
- **Cache:** a small amount of very fast memory close to the CPU that stores frequently used data and instructions.
- **Core:** a processing unit within a CPU that can carry out the fetch-decode-execute cycle independently.
- **Bus:** a set of parallel wires that transfers data or signals between components.
- **Stored program:** a program whose instructions are held in main memory, together with the data, as binary.
- **Von Neumann architecture:** a computer design in which data and instructions are stored in the same memory and fetched by the CPU one at a time.
- **Embedded system:** a computer system built into a larger device to perform a dedicated function.
- **Parallel processing:** carrying out several parts of a task at the same time on different processors or cores.

## Worked examples

**1. Describe the fetch stage of the fetch-decode-execute cycle. [3]**

The address of the next instruction is held in the program counter and copied to the memory address register [1]. The instruction at that address is sent from memory along the data bus to the memory data register / CIR [1]. The program counter is incremented [1].

**2. A computer has a 3 GHz CPU with 2 cores. A new computer has a 3 GHz CPU with 8 cores. Explain why the new computer might run a video-editing program faster. [3]**

More cores means more instructions can be processed at the same time [1]. A video-editing program can split its work into parts (e.g. different frames) [1] that run in parallel on separate cores, so the task finishes sooner [1].

**3. A washing machine contains an embedded system. (a) State what is meant by an embedded system. [1] (b) Give two reasons why an embedded system is used rather than a general-purpose computer. [2]**

(a) A computer system built into a device to carry out a specific/dedicated task [1].
(b) Any two: cheaper/smaller; uses less power; only needs to do one function; more reliable as it has one simple program; responds in real time [2].

**4. Describe the purpose of the control unit and the ALU. [2]**

Control unit: decodes instructions and sends control signals to coordinate the other components [1]. ALU: performs arithmetic and logic operations (e.g. add, compare) [1].

## Common mistakes

- Saying "the CPU stores the data". The CPU **processes**; RAM holds programs and data in use; secondary storage holds them long term.
- Writing that the cache is "part of the RAM". Cache is **separate** and much faster; it sits on or near the CPU.
- Mixing up the buses: the **address bus** carries addresses (one way); the **data bus** carries the data.
- Saying "clock speed is how fast the computer is" with no detail. Say **the number of cycles per second**, and that more cycles means more instructions executed per second.
- Forgetting the PC is **incremented** during fetch.
- "More cores = faster" with no condition. Software must be able to use the extra cores.
- Saying an embedded system is "a small computer". Say it is built **into a device** for a **dedicated function**.
