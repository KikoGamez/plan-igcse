# Computers: memory, storage, software and languages

> **In the exam:** Paper 1 (2 hours, 80 marks), roughly 8–14 marks. Typical tasks: compare RAM and ROM (2–3 marks), explain virtual memory or cache (2 marks), choose and justify a storage device for a situation (3–4 marks), describe functions of an operating system (2–4 marks), name and describe utility software (1–2 marks each), say what a high-level and a low-level language are (2 marks) and compare a compiler and an interpreter (3–4 marks). Always link your answer to the scenario in the question.

## What you need to know

- Types of memory: **RAM, ROM, cache, virtual memory**.
- How data is stored on **magnetic, optical and solid state** devices; **cloud** storage and other contemporary storage.
- What an **operating system** is and what it manages: files, processes, hardware, user interface.
- **Utility software**: managing, repairing and converting files; compression; defragmentation; backing up; anti-malware.
- **System software** vs **application software**; software that **simulates and models** the real world.
- **High-level and low-level** languages and their suitability; **assembler, compiler, interpreter** and their advantages and disadvantages.

## Notes

### Memory

| | RAM (random-access memory) | ROM (read-only memory) |
|---|---|---|
| Purpose | Holds the programs and data **currently in use** | Holds the **start-up (bootstrap) program** / firmware |
| Volatile? | **Volatile**: loses its contents when power is off | **Non-volatile**: keeps contents without power |
| Read/write | Read and write | Normally **read only** |
| Size | Large (GBs) | Small |

- **Cache:** small, very fast memory on or near the CPU that stores frequently used instructions and data. Faster than RAM but smaller and more expensive.
- **Virtual memory:** when RAM is **full**, the operating system uses part of the **secondary storage** (e.g. hard drive or SSD) as if it were RAM, moving unused data out and bringing it back when needed. It lets more programs run, but is **much slower** than real RAM, so too much use slows the computer ("thrashing").

Speed order (fastest first): registers, cache, RAM, secondary storage.

### Secondary storage

Secondary storage is **non-volatile** and holds programs and data **permanently** (when the power is off), with much greater capacity than RAM.

| Type | How data is stored | Example | Points |
|---|---|---|---|
| **Magnetic** | Tiny areas on spinning platters are magnetised in one of two directions (1 or 0); read/write head moves over the surface | Hard disk drive (HDD) | Large capacity, **cheap per GB**; **moving parts** so can be damaged by knocks, slower, noisier, heavier |
| **Optical** | A **laser** reads (and burns) **pits and lands** on a disc; reflected light is read as 1s and 0s | CD, DVD, Blu-ray | Cheap, portable, good for distributing media; low capacity, slow, easily scratched |
| **Solid state** | **Flash memory**: electrical charge trapped in transistors (cells); **no moving parts** | SSD, USB memory stick, SD card | **Fast**, silent, durable, low power; **more expensive per GB**; limited number of write cycles |

**Choosing a device:** consider **capacity, speed, cost, portability, durability, reliability**. Example: for a camera storing photos while you travel, use an SD card (flash): small, light, no moving parts so robust, low power.

**Cloud storage:** data is stored on **remote servers** accessed over the internet.
- Advantages: access from any device/anywhere; no need to buy/maintain your own hardware; easy to share; backed up by the provider; can increase storage easily.
- Disadvantages: needs **internet connection**; ongoing **subscription cost**; **security and privacy** concerns (provider or hackers could access data); you depend on the provider.

### Operating systems

An **operating system (OS)** is **system software** that manages the computer's hardware and software and provides an interface for the user. Examples: Windows, macOS, Linux, Android, iOS.

Functions:
- **File management:** creates, names, organises, moves, copies and deletes files and folders; controls access.
- **Process management / multitasking:** loads programs into memory, shares CPU time between them so several run at once; **memory management** keeps programs from overwriting each other.
- **Hardware management:** controls input/output and peripheral devices using **device drivers** (software that lets the OS communicate with a particular device).
- **User interface:** lets the user interact with the computer: **GUI** (windows, icons, menus, pointer; easy for beginners) or **command-line interface** (typed commands; powerful but must be learned).
- Also: **security** (user accounts, passwords, permissions) and handling of errors and interrupts.

### Types of software

- **System software:** runs and manages the computer: **operating system, utility software, device drivers, language translators**.
- **Application software:** lets the user do a task: word processor, spreadsheet, web browser, game, photo editor.

**Utility software** (system software that maintains or improves the computer):

| Utility | What it does |
|---|---|
| **File management** (managing, converting, repairing files) | Organises files; converts formats; repairs damaged files |
| **Compression** | Makes files smaller to save space or speed up transfer |
| **Defragmentation** | Rearranges the **fragments** of files on a **hard disk** so each file is stored together, making access faster (not needed on SSDs) |
| **Backup** | Makes a copy of data so it can be restored after loss, damage or attack |
| **Anti-malware** (antivirus, anti-spyware) | Scans for, detects, quarantines and removes malicious software |

**Simulation and modelling software** uses a computer model of real-world behaviour (e.g. flight simulator, weather, traffic, crash testing, spreadsheets for forecasting). Benefits: **safer, cheaper, faster** than real tests; can try "what if" scenarios and run situations that would be too dangerous or impossible; but results are only as good as the model and data.

### Programming languages

- **High-level language** (e.g. Python, C#, Java): close to human language (English-like). **Easier to read, write, debug and maintain**; portable (works on different processors after translation); one statement = many machine instructions. Must be **translated**.
- **Low-level languages:**
  - **Machine code:** binary instructions that the CPU runs directly. Specific to a processor.
  - **Assembly language:** uses short mnemonics (e.g. ADD, LDA) that map nearly one-to-one to machine code; translated by an **assembler**.
  - Low-level code is **harder to write, read and debug**, specific to one type of processor (**not portable**), but gives **direct control of hardware**, can be very **fast and memory-efficient**. Used for **embedded systems**, device drivers and where speed or size is critical.

### Translators

| | Compiler | Interpreter | Assembler |
|---|---|---|---|
| Translates | **whole** high-level program into machine code (one go) | **one line at a time** and runs it | assembly language into machine code |
| Output | A separate **executable file** | No file kept; runs line by line | machine code |
| Speed of running | **Fast** once compiled | **Slower** (translated each time) | – |
| Errors | Reports **all errors after** compiling attempt; none run until fixed | **Stops at the first error**, handy for testing | – |
| Source code | Not needed to run (can keep it private) | Needed every time | – |
| Good for | Finished programs sold or distributed | Development and testing; learning | Low-level programs |

## Key terms and definitions

- **RAM:** volatile main memory that holds the programs and data currently in use.
- **ROM:** non-volatile memory whose contents can normally only be read; stores the boot-up instructions.
- **Volatile:** loses its contents when the power is turned off.
- **Cache:** a small amount of fast memory that stores frequently used data and instructions close to the CPU.
- **Virtual memory:** secondary storage used as an extension of RAM when RAM is full.
- **Secondary storage:** non-volatile storage that keeps programs and data when the computer is off.
- **Operating system:** system software that manages the computer's hardware, software and files and provides a user interface.
- **Utility software:** system software that carries out maintenance tasks such as backup, compression, defragmentation and anti-malware.
- **Device driver:** software that allows the operating system to communicate with a hardware device.
- **High-level language:** a programming language that uses English-like statements and is independent of the processor.
- **Low-level language:** a programming language that is close to machine code and specific to a processor (machine code and assembly).
- **Compiler:** translates the whole of a high-level program into machine code before it is run.
- **Interpreter:** translates and executes a high-level program one line at a time.
- **Assembler:** translates assembly language into machine code.

## Worked examples

**1. Give three differences between RAM and ROM. [3]**

RAM is volatile, ROM is non-volatile [1]. RAM can be read and written, ROM is (normally) read-only [1]. RAM holds the programs and data currently in use, ROM holds the start-up program [1]. (Also: RAM is much larger.)

**2. A photographer needs a storage device to carry thousands of photos on location. Justify a suitable storage device. [3]**

Solid state/flash (e.g. SD card or portable SSD) [1] because it has no moving parts so is robust if knocked/dropped [1] and it is small, light and fast to transfer files, with large capacity [1].

**3. Describe two functions of an operating system. [4]**

Any two with a description: file management: creates, organises, copies, deletes files and folders [2]; managing hardware: uses device drivers to control input and output devices [2]; memory/process management: loads programs and shares CPU time so several programs run at once [2]; user interface: provides a GUI or command line so the user can interact [2]; security: user accounts and passwords [2].

**4. Compare a compiler and an interpreter. [4]**

A compiler translates the whole program in one go into an executable file [1]; an interpreter translates and runs one line at a time [1]. The compiled program runs faster and can be run without the source code [1]; an interpreter stops at the first error, so is better for testing, but the program runs more slowly [1].

## Common mistakes

- Saying ROM is "permanent" and RAM is "temporary" with no mention of **power loss**. Use the words **volatile** and **non-volatile**.
- Saying virtual memory is "extra RAM chips". It is **space on secondary storage**.
- Confusing RAM (main memory) with secondary storage. RAM is not where you save files long-term.
- Saying SSDs "have no moving parts so are faster" and stopping; add **durable, silent, low power** and note they cost more per GB.
- Defragmentation on an SSD. It is for **magnetic hard drives**.
- Describing the OS as "Windows" only. Describe what it **does** (manage files, processes, hardware, user interface).
- Saying an interpreter "does not translate". It does translate, one line at a time, every time.
- Saying low-level languages are "faster for everything". They give direct control and can be efficient, but they are hard to write and not portable.
