## Notes

### Variables, constants and data types

| Type | Stores | Example |
|---|---|---|
| **INTEGER** | whole numbers | 42, −7 |
| **REAL** | numbers with a decimal part | 3.14, −0.5 |
| **CHAR** | a **single character** | "A", "7" |
| **STRING** | **text** (zero or more characters) | "Madrid", "07700" |
| **BOOLEAN** | TRUE or FALSE | TRUE |

Phone numbers and postcodes are **STRING** (leading zeros, no arithmetic). A **variable** can change while the program runs; a **constant** cannot (`CONSTANT VAT ← 0.21`). Use constants for fixed values so they only need changing in **one place**.

```
DECLARE Price : REAL
DECLARE Quantity : INTEGER
CONSTANT Tax ← 0.2
```

### Selection and iteration

Use `IF … THEN … ELSE … ENDIF`, `CASE OF … ENDCASE` and the loops `FOR…NEXT`, `WHILE…DO…ENDWHILE`, `REPEAT…UNTIL` (see Algorithm design). **Nested** means one structure inside another, e.g. an IF inside a FOR.

Useful operators: `MOD` (remainder), `DIV` (whole-number division), `^` power. **Even number test:** `Number MOD 2 = 0`. **Divisible by 5:** `Number MOD 5 = 0`.

### String handling

| Operation | Pseudocode | Example result |
|---|---|---|
| Length | `LENGTH("Hello")` | 5 |
| Substring (text, start position, number of characters) | `SUBSTRING("Computer", 1, 3)` | "Com" |
| Upper case | `UCASE("hello")` | "HELLO" |
| Lower case | `LCASE("Hello")` | "hello" |
| Join (concatenate) | `"Hello" & " " & "Ann"` | "Hello Ann" |

The first character is **position 1** in the Cambridge guide. If a question uses another form of string function it will explain it; follow the question.

Loop through a string with `FOR I ← 1 TO LENGTH(Word)` and `SUBSTRING(Word, I, 1)`.

### Library routines

- `ROUND(7.4567, 2)` gives 7.46 (rounds to the given number of decimal places).
- `RANDOM()` returns a random real number from 0 to 1; scaling and rounding gives other ranges, e.g. `ROUND(RANDOM() * 10, 0)` gives a whole number from 0 to 10. Use the definition given in the question.

A **library routine** is a pre-written, pre-tested subroutine that you can use in your program, saving time.

### Arrays

An **array** stores **several items of the same data type** under **one name**, accessed by an **index**. This is better than 30 separate variables because a **loop** can process them all.

```
DECLARE Marks : ARRAY[1:30] OF INTEGER
FOR I ← 1 TO 30
   INPUT Marks[I]
NEXT I
```

**Two-dimensional array** (a table of rows and columns): `Grid[row, column]`.

```
DECLARE Scores : ARRAY[1:3, 1:4] OF INTEGER    // 3 students, 4 tests
FOR Student ← 1 TO 3
   FOR Test ← 1 TO 4
      INPUT Scores[Student, Test]
   NEXT Test
NEXT Student
```

`Scores[2, 3]` is student 2's third test. A 2D array needs a **nested loop** to visit every element.

### Procedures and functions

| | Procedure | Function |
|---|---|---|
| Returns a value? | **No** | **Yes**, exactly one, with `RETURN` |
| Called by | `CALL Name(...)` as a statement | Used **in an expression**: `X ← Name(...)` |

```
PROCEDURE ShowMenu()
   OUTPUT "1. Play"
   OUTPUT "2. Quit"
ENDPROCEDURE

CALL ShowMenu()
```

```
FUNCTION Average(Total : REAL, Count : INTEGER) RETURNS REAL
   RETURN Total / Count
ENDFUNCTION

Mean ← Average(250, 5)
```

**Parameters** are the values **passed into** a subroutine. Why use subroutines: **break the program into manageable parts (decomposition)**, **reuse** code, make it **easier to test and maintain**.

**Local variable:** declared **inside** a subroutine; exists and can be used **only there**; the memory is freed afterwards. **Global variable:** declared **outside**, usable **everywhere**, but any part of the program can change it, which can cause hard-to-find bugs. Prefer **local variables and parameters**.

### File handling

Data in variables is lost when the program ends; a **text file** stores it permanently.

```
OPENFILE "Scores.txt" FOR WRITE
WRITEFILE "Scores.txt", "Ana,75"
CLOSEFILE "Scores.txt"
```

```
OPENFILE "Scores.txt" FOR READ
WHILE NOT EOF("Scores.txt") DO
   READFILE "Scores.txt", Line
   OUTPUT Line
ENDWHILE
CLOSEFILE "Scores.txt"
```

`FOR READ` reads, `FOR WRITE` creates/overwrites, `FOR APPEND` adds to the end. **EOF** (end of file) becomes true when there is no more data. Always **close** the file. Exam papers usually show the file commands they expect, so copy their form exactly.

### Writing good programs

- **Meaningful identifier names** (`TotalScore`, not `x`).
- **Comments** (`// calculate VAT`) to explain code.
- **Indentation** to show structure.
- Use **subroutines** and **constants**.

These make a program easier to **read, debug and maintain**.

## Key terms and definitions

- **Variable:** a named memory location that stores a value that can change.
- **Constant:** a named value that does not change during the running of the program.
- **Array:** a data structure that stores a set of data items of the same data type under one identifier.
- **Procedure:** a subroutine that performs a task but does not return a value.
- **Function:** a subroutine that returns a value.
- **Parameter:** a value passed into a subroutine.
- **Local variable:** a variable that can only be used within the subroutine in which it is declared.
- **Global variable:** a variable that can be used anywhere in the program.
- **Library routine:** a pre-written, tested subroutine available to use in a program.
- **Concatenation:** joining two or more strings together.

## Worked examples

**1.** *Write a program that inputs 10 whole numbers, stores them in an array and outputs the total and the number of even values. [6]*

```
DECLARE Numbers : ARRAY[1:10] OF INTEGER
Total ← 0
EvenCount ← 0
FOR I ← 1 TO 10
   INPUT Numbers[I]
   Total ← Total + Numbers[I]
   IF Numbers[I] MOD 2 = 0 THEN
      EvenCount ← EvenCount + 1
   ENDIF
NEXT I
OUTPUT "Total: ", Total
OUTPUT "Even numbers: ", EvenCount
```

Marks: array declared [1]; total and count initialised [1]; FOR loop 1–10 with input into array [1]; total updated [1]; MOD 2 test and count [1]; both outputs [1].

**2.** *Write a function `Area` that takes a length and width (both REAL) and returns the area. Show a statement that uses it. [4]*

```
FUNCTION Area(Length : REAL, Width : REAL) RETURNS REAL
   RETURN Length * Width
ENDFUNCTION

OUTPUT Area(4.5, 2)
```

Header with parameters and RETURNS [1]; correct calculation [1]; RETURN [1]; ENDFUNCTION and a correct call [1].

**3.** *A password must be at least 8 characters, and must not be "password". Write pseudocode that repeats until a valid one is entered. [5]*

```
REPEAT
   INPUT Password
UNTIL LENGTH(Password) >= 8 AND LCASE(Password) <> "password"
OUTPUT "Accepted"
```

REPEAT/UNTIL [1], input [1], length test [1], second condition with AND [1], output [1].

## Common mistakes

- Using **STRING** for numbers you need to calculate with, or **INTEGER** for phone numbers.
- Off-by-one with arrays: declaring `[1:10]` then looping `1 TO 11`.
- Using a **function without RETURN**, or **calling a function as a statement** and discarding the result.
- Using a **global variable** when a parameter and local variable would do.
- Forgetting to **initialise** totals/counts or to **reset** them inside nested loops.
- Not closing files, or reading a file without testing **EOF**.
- Answering a "write a program" question with a vague description instead of **actual code**; a stray `=` instead of `←` for assignment.
- Using `ELSEIF` or other keywords not in the Cambridge guide. Nest IFs.
