# Networks and the internet

> **In the exam:** Paper 1 (2 hours, 80 marks), usually the biggest block of definitions and explanations after programming: about 10–16 marks. Typical tasks: name a network type or topology for a scenario and justify it (2–4 marks), compare client-server and peer-to-peer (2–3 marks), describe packet switching or the TCP/IP layers (3–4 marks), say what a protocol is and match protocols to uses (1–3 marks), describe the role of a router, switch, DNS or IP address (1–2 marks each), and give network security measures (2–4 marks).

## What you need to know

- Why computers are **networked**; **LAN, WAN, PAN**; **client-server** and **peer-to-peer**.
- **Wired and wireless** connections; data speeds in **bits per second** (Mbps, Gbps).
- **Protocols**: Ethernet, Wi-Fi, TCP/IP, HTTP, HTTPS, FTP, email (POP3, SMTP, IMAP).
- **Packets**, layered protocol stacks and the **4-layer TCP/IP model** (application, transport, network, data link).
- **Topologies**: bus, ring, star, mesh.
- Mobile standards (3G, 4G and later).
- **Network security**: access control, physical security, firewalls (cyber-attacks are in the next topic).
- The **internet** and the **world wide web**: IP addresses (IPv4, IPv6), **DNS**, URLs, ISP, HTTP/HTTPS, HTML.
- Components: **modem, router, switch, wireless access point (WAP)**.

## Notes

### Why network computers?

To **share** files, software, printers and an internet connection; **communicate** (email, messaging, video calls); **centralise** storage, backup and security; and **manage users** from one place.

### Types of network

| Type | Meaning | Example |
|---|---|---|
| **PAN** (personal area network) | A few metres around one person | Phone linked to earbuds/smartwatch by Bluetooth |
| **LAN** (local area network) | One **small geographical area**, usually one building or site; owned and managed by one organisation | School network |
| **WAN** (wide area network) | Covers a **large geographical area**; often uses **leased or public** telecoms lines; links LANs | The internet; a company linking offices in different countries |

### Client-server and peer-to-peer

| | Client-server | Peer-to-peer (P2P) |
|---|---|---|
| Structure | Clients request services from a central **server** | All computers are equal; each shares its own files/resources |
| Management | **Centralised**: easier backup, security, user accounts | No central control; each user manages their own |
| Cost | Server and admin are expensive | Cheap; no server needed |
| Reliability | Server failure stops service; but one server can be well protected and backed up | No single point of failure; but less secure and harder to back up |
| Use | Schools, businesses, web, email | Small home networks, file sharing |

### Wired vs wireless

| | Wired (e.g. Ethernet cable, fibre) | Wireless (Wi-Fi, Bluetooth, mobile) |
|---|---|---|
| Speed | Usually **faster and more stable** | Slower, can vary |
| Security | More secure (needs physical access) | Can be **intercepted**; needs encryption |
| Mobility | Fixed in place | **Devices can move**; no cables, easy to add devices |
| Interference | Little | Walls, distance and other signals cause **interference** |

**Data transfer speed** is measured in **bits per second**: Mbps (megabits per second), Gbps (gigabits per second). A line of 100 Mbps moves 100 million bits per second. To change to bytes divide by 8: 100 Mbps = 12.5 megabytes per second. (Note: lower-case "b" = bit, capital "B" = byte.)

**Mobile standards:** 3G, 4G, 5G… each generation gives **faster speeds** and more capacity (4G is fast enough for HD video; 5G is faster still with lower delay).

### Network topologies

| Topology | How it is connected | Advantages | Disadvantages |
|---|---|---|---|
| **Star** | Every device connects to a **central switch** | Failure of one cable affects only that device; easy to add devices; good performance | Central switch is a **single point of failure**; needs more cable |
| **Bus** | All devices share **one main cable (backbone)** | Cheap, little cable | Breaking the backbone stops the network; collisions and slow when busy |
| **Ring** | Each device connects to two others in a **circle**; data travels one way | Orderly access | One break can stop the network; adding a device disrupts it |
| **Mesh** | Devices connect to **many or all** others | Many routes, so **very reliable**; no single failure; data can take another path | **Expensive**, lots of cabling/connections; complex |

Most school and home LANs use the **star** topology.

### Network hardware

- **Switch:** connects devices **within a LAN**; sends data **only to the device it is meant for** (using MAC addresses).
- **Router:** connects **different networks** (e.g. your LAN to the internet) and **directs packets** towards their destination using IP addresses; usually includes a firewall and wireless access point at home.
- **Wireless access point (WAP):** lets wireless devices connect to a wired network.
- **Modem:** converts between the digital signals of a computer and the signals used on a telephone, cable or fibre line, so you can reach your ISP.
- **Network interface card (NIC):** each device has one; it has a unique **MAC address**.

### Protocols

A **protocol** is a **set of rules** that devices follow so they can communicate (how data is formatted, sent and checked).

| Protocol | Use |
|---|---|
| **Ethernet** | Rules for **wired** LANs |
| **Wi-Fi** | Rules for **wireless** LANs |
| **TCP/IP** | Rules for splitting data into packets, addressing and routing across networks (the basis of the internet) |
| **HTTP** | Transfers web pages |
| **HTTPS** | HTTP with **encryption** (secure web pages) |
| **FTP** | **Transferring files** between computers |
| **SMTP** | **Sending** email |
| **POP3** | **Downloads** email to your device (usually removed from the server) |
| **IMAP** | Accesses email **kept on the server**; stays in sync across devices |

### Packets and TCP/IP

Data sent across a network is split into **packets** (**packet switching**). Each packet contains:
- a **header**: source and destination **IP address**, **packet number** (to put them back in order), and other control information (e.g. protocol, time to live);
- the **payload** (the data);
- a **trailer** or error check (checksum).

Each packet can take a **different route** through routers, then they are **reassembled in order** at the destination. A lost or corrupted packet can be re-sent.
Advantages: uses the network efficiently; if one route is busy or broken, packets use another; a failure only requires re-sending a few packets.

**Layers:** a **protocol stack** divides networking into layers; each layer does one job and uses the layer below. Layers make it easier to **develop, test and change** one part without altering others.

| TCP/IP layer | Job |
|---|---|
| **Application** | Programs use protocols such as HTTP, FTP, SMTP |
| **Transport** | TCP splits data into packets, numbers them, and checks they arrive (re-sends if not) |
| **Network** (internet) | **IP** adds IP addresses and **routes** packets |
| **Data link** | Sends frames over the physical connection (Ethernet, Wi-Fi) using MAC addresses |

### The internet and the world wide web

- The **internet** is a **global network of networks** (the infrastructure: cables, routers, servers).
- The **world wide web (WWW)** is a **service on the internet**: a collection of **web pages** accessed using a browser and **HTTP/HTTPS**, written in **HTML**, stored on **web servers**.
- **URL** (uniform resource locator): the address of a web page, e.g. `https://www.example.com/page.html` → protocol, **domain name**, file path.
- **ISP** (internet service provider): a company that gives you access to the internet.
- **IP address:** a unique number that identifies a device on a network.
 - **IPv4:** **32 bits**, written as four denary numbers 0–255 separated by dots, e.g. 192.168.1.10. About 4.3 billion addresses (2³²), which has run out.
 - **IPv6:** **128 bits**, written in hexadecimal groups, e.g. 2001:0db8:85a3::8a2e:0370:7334. Vastly more addresses. Needed because of the number of devices.
 - Standards are needed so that all devices and networks can understand each other's addresses.
- **DNS (domain name system):** like a phone book: servers that **translate a domain name** (www.example.com) into an **IP address**. When you type a web address, your browser asks a DNS server for the IP address, then connects to the web server at that IP address.

### Network security (protection)

- **Access control:** usernames, strong passwords, **different access levels/permissions** for different users, two-factor authentication, biometrics.
- **Physical security:** locked server rooms, key cards, CCTV, security staff.
- **Firewall:** hardware or software that **monitors incoming and outgoing traffic** against rules and **blocks** unauthorised or suspicious traffic.
- Also: encryption of data and Wi-Fi (WPA2/WPA3), anti-malware, regular software updates, backups.

## Key terms and definitions

- **Network:** two or more computers connected together to share data and resources.
- **LAN:** a network covering a small geographical area, such as a building or school.
- **WAN:** a network covering a large geographical area, often linking LANs.
- **Protocol:** a set of rules that allows devices to communicate.
- **Packet:** a small chunk of data sent across a network with a header containing addressing information.
- **Router:** a device that connects networks together and directs packets to their destination.
- **Switch:** a device that connects devices on a LAN and forwards data only to the intended device.
- **IP address:** a unique address given to a device on a network.
- **DNS:** a system that translates domain names into IP addresses.
- **The internet:** a global network of interconnected networks.
- **World wide web:** a collection of web pages accessed over the internet using HTTP/HTTPS.
- **Firewall:** software or hardware that monitors network traffic and blocks unauthorised access.
- **Topology:** the way in which the devices in a network are arranged and connected.

## Worked examples

**1. A school wants to connect 200 computers in one building. (a) Name the type of network. [1] (b) Name and describe a suitable topology, giving one advantage. [3]**

(a) **LAN** [1].
(b) **Star** topology [1]: every device is connected to a central switch [1]. Advantage: if one cable fails only one device is affected / easy to add devices [1].

**2. Describe how a file is sent across the internet using packets. [4]**

The file is split into packets [1]. Each packet has a header with the source and destination IP address and a packet number [1]. Packets may travel by different routes through routers [1]. At the destination they are reassembled in the right order using the packet numbers [1]. (Missing packets are re-requested.)

**3. Explain what happens when a user types www.example.com into a browser. [3]**

The browser sends the domain name to a DNS server [1], which returns the IP address of the web server [1]. The browser connects to that IP address and requests the page using HTTP/HTTPS [1].

**4. State two differences between a client-server and a peer-to-peer network. [2]**

In client-server a central server provides services and manages the network, whereas in peer-to-peer all computers are equal and share their own files [1]. Client-server is easier to back up and secure centrally but is more expensive; peer-to-peer is cheap but harder to secure [1].

## Common mistakes

- Saying "the internet is the world wide web". The web is **one service that runs on** the internet.
- Mixing up switch and router: a **switch** connects devices **inside** a LAN; a **router** connects **different networks** and sends packets between them.
- Forgetting that DNS translates **domain names to IP addresses**.
- Saying "a protocol is a program". It is a **set of rules**.
- Giving a topology advantage that is the same as another's ("it is faster"). Be specific: single cable failure, central switch, many routes.
- Confusing SMTP (send) with POP3/IMAP (receive).
- Mixing up Mbps and MBps; speeds use **bits**.
- Saying HTTPS "makes a site safe". It **encrypts** the data between browser and server; the website could still be malicious.
