# Databases and SQL

> **In the exam:** **Paper 2 (Algorithms, Programming and Logic, 1 h 45, 75 marks)**, syllabus section 9 (Databases). A database question usually gives you a **table of about 5–8 records** and asks: state the number of fields/records (1 mark each), choose a **primary key** and a **data type** (1–2 marks), complete or write an **SQL query** (3–6 marks) and state the **output** of a query (2–4 marks). It is typically one question worth about 8–10 marks.

## What you need to know

- A **database** stores organised data. Cambridge uses a **single table**.
- **Table, record, field**; **primary key**.
- **Data types**: text/alphanumeric, character, Boolean, integer, real, date/time.
- Using **SQL**: `SELECT`, `FROM`, `WHERE`, `ORDER BY` (`ASC`/`DESC`), and the functions `SUM` and `COUNT`.
- Using `AND`, `OR` and comparison operators in conditions.
- **Validation** of data entered into a database.

## Notes

### Terms

A **database** is an organised collection of data. A **table** is made of **rows and columns**.

| CarID | Make | Colour | Year | Price | Available |
|---|---|---|---|---|---|
| 1 | Ford | Red | 2019 | 8500 | TRUE |
| 2 | Kia | Blue | 2021 | 12000 | TRUE |
| 3 | Ford | Blue | 2017 | 6000 | FALSE |
| 4 | Audi | Black | 2020 | 21000 | TRUE |
| 5 | Kia | Red | 2018 | 9000 | FALSE |
| 6 | Ford | Black | 2022 | 15000 | TRUE |

- A **field** is **one column**, one item of data about each thing (`Make`). This table has **6 fields**.
- A **record** is **one row**, all the data about one thing (the whole of car 3). This table has **6 records**.
- The **primary key** is a field that holds a **unique value for every record**, so each record can be identified. Here, `CarID`. A name or `Make` would **not** work, because values repeat.
- The **field names** are the headings in the first row; they are not records.

### Data types

| Data type | Use | Example |
|---|---|---|
| **Text / alphanumeric** | Letters, digits, symbols | Make, a phone number, a postcode |
| **Character** | A single character | Grade "B" |
| **Integer** | Whole number you may calculate with | Year |
| **Real** | Number with a decimal part | Price 8.99 |
| **Boolean** | **TRUE/FALSE** (yes/no) | Available |
| **Date/time** | A date and/or time | Date of birth |

Phone numbers are **text**, not integer: they can start with 0 and are never added up.

### SQL (Structured Query Language)

SQL lets you **search a database and retrieve data**. Learn this order of keywords:

```
SELECT field1, field2
FROM table
WHERE condition
ORDER BY field ASC/DESC;
```

- `SELECT` names the **fields to show** (`*` means **all fields**).
- `FROM` names the **table**.
- `WHERE` gives the **condition** records must meet.
- `ORDER BY` sorts the output: `ASC` ascending (default), `DESC` descending.
- Finish with a **semicolon**. Text is written **in quotes**; numbers and TRUE/FALSE are not.

Comparison operators: `=` `<>` (not equal) `<` `>` `<=` `>=`. Combine conditions with `AND`, `OR`.

**Examples using the Car table**

| Query | Output |
|---|---|
| `SELECT Make, Price FROM Car WHERE Colour = "Red";` | Ford 8500; Kia 9000 |
| `SELECT CarID FROM Car WHERE Make = "Ford" AND Price < 10000;` | 1; 3 |
| `SELECT CarID FROM Car WHERE Colour = "Blue" OR Colour = "Black";` | 2; 3; 4; 6 |
| `SELECT Make, Year FROM Car WHERE Year >= 2020 ORDER BY Year ASC;` | Audi 2020; Kia 2021; Ford 2022 |
| `SELECT * FROM Car ORDER BY Price DESC;` | all fields, cars in order 4, 6, 2, 5, 1, 3 |
| `SELECT COUNT(*) FROM Car WHERE Available = TRUE;` | 4 |
| `SELECT SUM(Price) FROM Car WHERE Make = "Kia";` | 21000 |

- **COUNT** returns the **number of records** that match.
- **SUM** returns the **total of a numeric field** for matching records.

### How to write a query (step by step)

1. **What** do they want to see? → `SELECT` those fields (copy the field names **exactly**).
2. **Which table?** → `FROM`.
3. **Which records only?** → `WHERE` (a condition per requirement, linked with AND/OR).
4. **In what order?** → `ORDER BY`.

"Show the make and price of all available cars, most expensive first" becomes `SELECT Make, Price FROM Car WHERE Available = TRUE ORDER BY Price DESC;`

### Validation in databases

Use **validation** (range, length, type, presence, format) to stop bad data being entered, e.g. a **range check** on `Year`, a **presence check** on the primary key. Also: **a primary key must be unique** so the system rejects duplicates.

## Key terms and definitions

- **Database:** an organised collection of related data.
- **Table:** a structure of rows and columns that holds data in a database.
- **Record:** a row in a table; all the data about one item.
- **Field:** a column in a table; one piece of data about each item.
- **Primary key:** a field that uniquely identifies each record in a table.
- **SQL:** Structured Query Language, a language used to search and retrieve data from a database.
- **Boolean:** a data type with only two possible values, TRUE or FALSE.
- **Validation:** an automatic check that data entered is reasonable.

## Worked examples

**1.** *Using the Car table, state (a) the number of records, (b) the number of fields, (c) the most suitable primary key, (d) the data type of Available. [4]*

(a) 6 [1] (b) 6 [1] (c) CarID [1] (d) Boolean [1]

**2.** *Write an SQL query to display the Make and Colour of all cars that cost less than $10,000, in alphabetical order of Make. [4]*

```
SELECT Make, Colour
FROM Car
WHERE Price < 10000
ORDER BY Make ASC;
```

SELECT with both fields [1]; FROM Car [1]; WHERE Price < 10000 [1]; ORDER BY Make [1]. Result: Ford Red (8500); Ford Blue (6000); Kia Red (9000), sorted by Make → Ford, Ford, Kia.

**3.** *State the output of: `SELECT COUNT(*) FROM Car WHERE Make = "Ford" AND Available = TRUE;` [1]*

Ford cars: 1 (TRUE), 3 (FALSE), 6 (TRUE) → **2** [1].

**4.** *Explain why Make is not suitable as a primary key. [1]*

Values are **not unique** (Ford appears three times) [1].

## Common mistakes

- Picking a **non-unique field** (name, make) as a primary key.
- **Confusing field and record**: fields are columns, records are rows. **Do not count the heading row** as a record.
- Writing **`WHERE` before `FROM`** or putting `ORDER BY` before `WHERE`.
- Forgetting **quotes around text** or adding them around numbers / TRUE / FALSE.
- Using **`AND` where the question needs `OR`**: "red **or** blue" is `Colour = "Red" OR Colour = "Blue"`; one record cannot have two colours at once.
- Mixing up **`COUNT`** (how many records) and **`SUM`** (total of values).
- Choosing **integer** for phone numbers, or **text** for a field used in calculations.
- Misspelling field names. Copy them exactly as in the table.

## Practice questions

Use the Car table above.

1. State the number of fields and the number of records in the table. [2]
2. State the data type of the field Price (values such as 8500 and 8999.99). [1]
3. Write an SQL query to display all the fields of all the cars made by Kia. [3]
4. Write an SQL query to display the CarID of all cars that are available and cost less than 15000. [4]
5. State the output of `SELECT Make FROM Car WHERE Year < 2019 ORDER BY Make DESC;`. [2]
6. Write an SQL query to find the total price of all the Ford cars. [3]
7. Explain why a primary key is needed in a database table. [2]
8. State the output of `SELECT COUNT(*) FROM Car WHERE Colour = "Black" OR Make = "Kia";`. [1]

2. Real (because it has decimals).
3. `SELECT * FROM Car WHERE Make = "Kia";` — SELECT * [1], FROM Car [1], WHERE condition [1].

6. `SELECT SUM(Price) FROM Car WHERE Make = "Ford";` — SUM(Price) [1], FROM Car [1], WHERE [1]. (Output 29500.)
7. It **uniquely identifies each record** [1] so records can be found/updated without confusing two records, and duplicates are prevented [1].
8. Black: cars 4 and 6; Kia: cars 2 and 5 → **4** records.
