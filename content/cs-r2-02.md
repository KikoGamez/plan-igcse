# Past paper · Paper 1 timed (2/2)

> **Goal:** Finish the rest of the same Paper 1, then mark the whole paper with the Pearson mark scheme and turn your lost marks into a short revision list.

## Before you start

- **Use the same paper** as the previous session, with the half you already did, plus the **mark scheme** for that paper (from the same Pearson past-paper page, or from your teacher). Keep the mark scheme closed until the timed part is finished.
- Have ready: pen for answering, a **different colour** pen for marking, a timer, and your list of "unsure" questions from last time.
- Today there are two parts: **finish the second half** (about 40 marks, which should take about 50–60 minutes at exam pace), then **mark**. If marking is not finished in the hour, finish it before you start new topic revision.

## Exam format reminder

- **Paper 1: Principles of Computer Science** (4CP0/01): **2 hours, 80 marks, 50%** of the International GCSE; multiple-choice, short open-response, open-response and extended open-response questions; all compulsory.
- Mock grade boundaries change each series, so do not rely on a fixed percentage. Pearson publishes boundaries for each series; use the same series as your paper if you want a rough grade, and treat it only as a guide.
- The second half often has the longer, scenario-based questions and the **6-mark extended answers**. These are worth a lot: do not leave them blank.

## How to do it

1. **0–3 min:** set the timer for 45 minutes. Remind yourself: 1 mark ≈ 1.5 minutes.
2. **3–45 min:** carry on from the line you drew last time and complete the rest of the paper under timed conditions. If you get stuck for more than 2 minutes, move on and star it. Save 5 minutes at the end for stars.
3. **45–48 min:** stop. If any question is blank, write something now (there is no penalty); then put the pen down.
4. **48–58 min:** start **marking** in a different colour with the mark scheme: first the **multiple-choice** and **calculation** questions (quick), then short answers. Write the mark in the margin and the **reason code** next to each lost mark: **K** knowledge, **T** technique, **C** careless, **R** ran out of time.
5. **58–60 min:** write the total so far. Keep the paper: the marking of the extended answers and the full tally continues after the session. When finished, add up both halves, count marks by **topic** (algorithms, programming, data, computers, networks, bigger picture), and list your **three weakest topics**. Revise those with the Round 1 notes.

## Exam technique for this paper

- **Do the sure marks first.** The first pass is for what you know; leave long questions until you have done the short ones in that section.
- **Extended questions (6 marks):** mention both advantages and disadvantages, use the scenario, and **finish with a conclusion**. Mark schemes usually have bands: a clear, balanced, developed answer gets top band even without every point.
- **Calculation questions:** show every line. Method marks are given even if the final answer is wrong. Include units (bytes, bits, Hz).
- **Pseudocode/trace questions:** write the value of every variable at every step; check for off-by-one errors (does the loop run n or n−1 times?).
- **Logic and truth tables:** work out the middle columns (e.g. A AND B) before the final column.
- **If you finish early,** go back to calculations and check them a different way (e.g. convert binary answers back to denary).
- **Do not run out of time on one question.** Giving 4 marks for a 2-mark question is a waste; the marks do not exist.

## Checklist while marking

- Use the mark scheme **exactly**. Where it lists acceptable alternatives, you can give the mark; where it says "do not accept", you cannot, even if you think it is almost right.
- A mark is given for a **point made**, not for sounding good. If you wrote "it is faster" and the scheme needs "because there are no moving parts", you did not earn it.
- For "explain" questions, check you have the **reason** as well as the point.
- Mark yourself as an examiner would: strict and fair. Do not give marks for "nearly".
- For each lost mark ask: could I have got this right if I had read the command word, the scenario, or the number of marks more carefully? That is **technique**; it is the fastest thing to fix.
- Tally: marks lost by reason (K/T/C/R) and by topic. Write them on the front page.
- For each **K** mistake, write the correct fact on a card or in your notes today. Re-do the matching Round 1 quiz tomorrow.
- Mark any extended answer by looking at the **indicative content** in the mark scheme and ticking the points you made; then decide which band it falls in.

## Quick-fire revision

- Two's complement: flip the bits, add 1; 8-bit range −128 to +127.
- A left shift multiplies by 2 each place; a right shift divides by 2 each place (arithmetic shift keeps the sign bit).
- Overflow: a result too big for the bits available; the carry out of the leftmost bit is lost.
- ASCII is 7 bits (128 characters); Unicode uses more bits and covers all languages.
- Caesar cipher: shift every letter by the key; Vigenère: repeating keyword; Rail Fence: zigzag rearrangement.
- Run-length encoding: AAABB → 3A2B; it can make files bigger if there are no repeats.
- Embedded system: computer built into a device for one dedicated job (washing machine, microwave).
- More cores means more tasks in parallel; larger cache means fewer slow trips to RAM; higher clock speed means more cycles per second.
- Optical uses a laser on pits and lands; magnetic uses magnetised platters; solid state uses flash with no moving parts.
- Operating system functions: files, processes/memory, hardware via drivers, user interface, security.
- Star topology: central switch, one cable fails = one device lost; mesh: many routes, expensive.
- HTTPS = HTTP with encryption; SMTP sends mail; POP3 downloads; IMAP syncs on the server.
- Open source: code freely available; proprietary: paid, code hidden; copyright protects works; patents protect inventions.
- Ethical hacking is authorised; penetration testing finds weaknesses before criminals do.
