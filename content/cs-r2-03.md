# Paper 2 practice: programming tasks (1/2)

> **Goal:** Practise Paper 2 (Application of Computational Thinking) the way it is sat: on a computer, in your programming language, with no internet, working through task-based questions under time pressure.

## Before you start

- **Paper to use:** a real Pearson Edexcel International GCSE Computer Science **Paper 2 (4CP0/02)** for the language you use in class (Python, C# or Java; the Pearson site lists a version for each). Get it from the Pearson past-papers page for the qualification, or from your teacher. Download **the data files** that go with it (text or CSV files the tasks read), and the **mark scheme/sample solutions** but keep these closed. Choose a paper you have not done.
- **Set up before the timer starts:** open your IDE or editor (the one you use at school, e.g. IDLE or Thonny for Python), create a new folder for this paper, copy the data files into it, and run a one-line "Hello" program to check the setup.
- **Exam rules to copy:** **no internet**, no notes, no help from other people. Use only the **pseudocode reference document** that comes with the paper (it explains the pseudocode style used in questions). Keep a pen and paper for planning: some answers are written on the paper, not on the computer.
- Have a timer. Phone away. Save your work every few minutes with a clear filename such as `q3_task.py`.
- Today you do the **first hour** of the paper, which is roughly the first third of the 80 marks (about 26–30 marks if you keep exam pace of 3 hours for 80 marks, around 2 minutes per mark). Next session you finish and compare with the solutions.

## Exam format reminder

- **Paper 2: Application of Computational Thinking**, code 4CP0/02. **3 hours, 80 marks, 50%** of the International GCSE, taken **on a computer** under supervision. You choose **one language: Python, C# or Java**, and must use only that one throughout.
- Question types: multiple-choice, short open-response, open-response, extended open-response and **task-based** questions. Task-based questions are carried out on the computer; written answers go in the question paper.
- It draws on: algorithms (interpret, amend, create), developing and testing code (data types, structures, input/output, operators, subprograms), **using data sources** (reading from and writing to files), binary and data representation, encryption and compression, and truth tables and logic.
- You can **run and test** your programs, so test them; working code earns the marks, and partly working code usually earns some.

## How to do it

1. **0–5 min:** read the front instructions and skim **all** the tasks. Note which are **write**, which **amend** and which **explain/test**. Check which files each task needs.
2. **5–50 min:** work through the tasks **in order** with the timer running. For each task: (a) underline what to **input**, **process**, **output**; (b) write 2–3 lines of plan on paper or as comments; (c) code it; (d) **run it** with normal, boundary and erroneous data; (e) save. Note the time at the end of each task.
3. **50–57 min:** go back to anything incomplete. Make sure the program **runs without errors**; a half-working program with a clear structure gets more marks than one that crashes. Add comments and meaningful variable names where missing.
4. **57–60 min:** save everything and write on the paper which question you were on and what is unfinished. Do **not** look at the solutions yet.

## Exam technique for this paper

- **Read the task twice.** Check exact **input prompts, output format, variable names and file names** that the question tells you to use. Marks are given for following them exactly.
- **Break the problem down:** input → process → output. Write a few comment lines first and fill in the code under each.
- **Start with what works.** Get a simple version running (e.g. read one line of the file and print it) and then extend it.
- **Use the constructs the question hints at:** a loop for repeated actions, `if/elif/else` for decisions, a function for a repeated task, a list/array for stored values, a 2D structure for table data.
- **Files:** open with the correct mode (read/write/append), read line by line, strip the newline and split fields; close the file or use `with`. Check the data types: convert text to int/float before doing arithmetic.
- **Validation:** if asked, check range, length, presence or type, and use a loop to ask again until valid.
- **Test as you go** with normal, boundary and erroneous data. A short test table written in the paper can earn marks in "test" questions.
- **Readability marks:** meaningful variable names, indentation, a comment or two, and no unnecessary repeated code.
- **Trace by hand** when an "amend" question gives code: read it line by line first and predict the output before running.
- **Written questions in the paper** (truth tables, binary, encryption, explain code) are worth the same per mark as the coding. Do them; they are quicker.
- If you get an error message, read the **last line first** and the **line number**: it usually says what kind of error it is (syntax, runtime), and where.

## Checklist while marking

You will mark next session, but plan for it: while you work, keep a note beside each task with how confident you are (✓ sure, ? unsure, ✗ not working). Next session you will check:

- Did the program **run** and produce the right output for the sample data?
- Did you use the **exact names and prompts** required?
- Did you handle each **requirement** in the question (read the file, validate, loop, output)?
- Were your **test data** (normal, boundary, erroneous) suitable?
- Is the code **readable** (comments, indentation, names)?

## Quick-fire revision

- Data types: integer, real (float), Boolean, char, string. Convert with `int()`, `float()`, `str()`.
- Operators: `+ - * /`, integer division `//`, modulus `%`; comparisons `== != < > <= >=`; logic `and or not`.
- Selection: `if / elif / else`. Iteration: `for` (count-controlled), `while` (condition-controlled).
- A list stores many values: `scores = []`, `scores.append(5)`, `scores[0]`, `len(scores)`.
- Strings: `len(s)`, slicing `s[0:3]`, `s.upper()`, `s.split(",")`, `s.strip()`.
- File reading: `with open("data.txt", "r") as f:` then `for line in f:`.
- File writing: mode `"w"` overwrites, mode `"a"` appends.
- A function takes parameters and returns a value; a procedure does a task without returning a value. Variables inside a function are local.
- Validation checks input is sensible (range, length, type, presence); verification checks it was entered correctly.
- Error types: syntax (breaks the rules), runtime (crashes while running), logic (wrong answer, no crash).
- Test data: normal (typical), boundary (at the edges), erroneous (should be rejected).
- Trace tables: one column per variable, one row per step.
- Linear search checks each item; binary search needs sorted data and halves the range each time.
- Bubble sort swaps neighbours; stop when a full pass has no swaps.
