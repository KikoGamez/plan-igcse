# Past paper · Paper 2 Algorithms, Programming and Logic timed

> **Goal:** Sit a full Cambridge IGCSE Computer Science Paper 2 in 1 h 45 under exam conditions, writing all pseudocode by hand, so you know your real mark and how well you manage the long programming question.

## Before you start

- **Paper:** a Cambridge IGCSE Computer Science **0478 Paper 2** (variant 21, 22 or 23) from a recent series you have **not** seen, e.g. May/June 2025 Paper 22, or October/November 2024 Paper 21 (the Feb/March series has variant 22 only). Use a paper from **2023 onwards**.
- The **mark scheme** for the same paper and variant: keep it closed until next session.
- **Timer** for **1 hour 45 minutes**. If you cannot do it in one go, sit it in **two blocks** and stop the clock exactly between them.
- **No calculator** and **no computer**: you write all code on paper. Have a **pencil** (you will redraw things), black pen, ruler, a **rubber** for pseudocode corrections.
- Keep your **pseudocode guide** closed. If you plan to answer in Python/Java/VB.NET rather than pseudocode, check with your teacher that that is what the school expects.
- Phone away, notes closed.

## Exam format reminder

- **Paper 2 Algorithms, Programming and Logic:** 1 hour 45 minutes, **75 marks**, **50%** of the IGCSE. **All questions compulsory.**
- Covers sections 7–10: **algorithm design and problem-solving** (flowcharts, trace tables, standard methods, testing), **programming**, **databases (SQL)** and **Boolean logic**.
- Question styles: **short answers** (state, name, data types, validation), **trace tables**, **complete / correct** given pseudocode, **SQL queries**, **truth tables and logic circuits**, and a **longer scenario question** where you write a program. The scenario question is the biggest single question on the paper; look at its marks when you skim.
- **Timing:** 75 marks in 105 minutes is **1.4 minutes per mark**. Programming marks are slower: allow more time for writing code and less for 1-mark items.

## How to do it

| Time | What to do |
|---|---|
| 0:00–0:05 | Skim all questions. Find the **scenario/programming** question and its marks. |
| 0:05–0:40 | First third: short and structured questions. Do the easy marks first. |
| 0:40–1:05 | Middle: trace tables, SQL, logic. Do each carefully; a trace table needs one line per change. |
| 1:05–1:35 | The **long programming question**: plan (underline inputs, processes, outputs), then write. |
| 1:35–1:45 | Return to skipped questions; check loops end, arrays use the right limits, every IF has ENDIF. |

Rules: stop at **1 h 45**. Anything you add after time should be in a different colour. **Never leave a coding question blank**: write the declaration, the loop and the input, which is often worth half the marks.

## Exam technique for this paper

- **Use Cambridge pseudocode forms:** assignment `←`, `DECLARE`, `FOR…NEXT`, `WHILE…ENDWHILE`, `REPEAT…UNTIL`, `IF…ENDIF`, `PROCEDURE…ENDPROCEDURE`, `FUNCTION…RETURNS…ENDFUNCTION`.
- **Indent** inside structures and use **meaningful names**; the examiner needs to follow it.
- **Trace tables:** one column per variable and output; change one cell per step; follow the order of execution exactly; do not "predict".
- **"State the purpose"** = say what the algorithm achieves overall (e.g. "finds the largest of the numbers"), not a line-by-line list.
- **SQL:** SELECT, FROM, WHERE, ORDER BY in order; quotes around text; semicolon; field names copied exactly.
- **Logic:** write each gate's output in an extra column; 3 inputs = 8 rows.
- **Programming:** initialise totals/counters, loop the **right number of times**, put the output **after** the loop if it is a total, and use the **validation loop** (REPEAT…UNTIL) when asked.
- Where the question says "using the following array/variable names", **use exactly those names**.
- Mark-scheme points are easy to get: **input, loop, condition, update, output**. Aim for each of these.

## Quick-fire revision

- Four stages: **analysis, design, coding, testing**.
- **Decomposition** = break into parts; **abstraction** = remove detail.
- Flowchart: **diamond = decision**, parallelogram = input/output, rectangle = process, rounded = start/end.
- `17 MOD 5 = 2`, `17 DIV 5 = 3`.
- **FOR** known number of repeats; **WHILE** may run zero times; **REPEAT** at least once.
- **Bubble sort:** compare adjacent pairs, swap, repeat until no swaps.
- **Linear search:** check each item in turn.
- Validation checks: **range, length, type, presence, format, check digit**.
- Verification: **visual check, double entry**.
- Test data: **normal, abnormal, extreme, boundary**.
- Array = many items, one name, accessed by an **index**; 2D needs a **nested loop**.
- Function **returns** a value; procedure does not.
- **Local** variable only in its subroutine; **global** everywhere.
- SQL: `SELECT … FROM … WHERE … ORDER BY …;` with `SUM` and `COUNT`.
- Gates: **XOR = different inputs**; NAND/NOR are the opposites of AND/OR.
