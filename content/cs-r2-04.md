## Exam format reminder

- **Paper 2: Application of Computational Thinking** (4CP0/02): **3 hours, 80 marks, 50%**, on a computer, one language only (Python, C# or Java), **no internet**.
- Later tasks usually combine skills: reading data from a file, processing it with loops, selection and lists, using functions, validating input and writing results to the screen or a file.
- Marks are given for **working code that meets the requirements**, for the **method** shown, and for **testing and explanation** parts written on the paper.
- The mark scheme normally lists the points needed and may give a model solution in one language; yours may look different and still earn the marks if it does the same job.

## How to do it

1. **0–5 min:** reopen the paper and files. Re-read the unfinished tasks and set a timer for 35 minutes. Write the marks for each task and give each task time of about 2 minutes per mark.
2. **5–35 min:** do the remaining tasks. For each: read twice, plan in comments, code a small first version, run it, then add features. If a task is stuck for 5 minutes, leave it with a comment of what you would do (partial plans may earn marks on paper) and move on.
3. **35–40 min:** stop coding. Run **every** program once more with the data given. Save. Write answers on the paper for the written parts (testing, explanation, trace) if not done.
4. **40–55 min:** **mark and compare.** Open the mark scheme. For each task, tick the marking points your program meets. Then compare your approach with the sample solution: how does it read the file, which loops, which variables?
5. **55–60 min:** fix the **two** most important problems in your code and re-run. Then write a **skills list**: top 3 things to practise (e.g. "split lines from CSV file", "2D list", "validation loop with while").

## Exam technique for this paper

- **Run the program before you move on** and check the output matches what the question describes. Syntax errors lose all marks for that code; fix them first.
- **File tasks:** know your template. Reading: `with open("file.txt") as f:` then loop; strip and split each line; convert numbers. Writing: `"w"` or `"a"`. Do not forget to **close** the file if you do not use `with`.
- **Totals, averages, max/min:** start with a variable before the loop (0 for total, first value for max), update inside the loop, give output after the loop.
- **Searching a list for a match:** loop through, compare, store a flag or the position, and report a message if not found.
- **Menus:** use a `while` loop that repeats until the user picks "quit", with `if/elif/else` inside.
- **Functions:** use parameters rather than global variables and **return** a value when asked.
- **2D data:** `table[row][column]`, with nested loops to go through everything.
- **Explain your code:** if a question asks you to explain how something works, name the construct (iteration, selection, subprogram) and say what it does in this program.
- **Spend marks wisely:** about 2 minutes per mark. Do not polish one task while others are blank.
- **Reading mark schemes:** note what the examiners accepted for variable names, and for outputs wording; follow the question's wording exactly.

## Checklist while marking

- Does your program **run without errors** on the supplied data?
- Does it **produce the correct output** in the format asked (text, order, decimal places)?
- Did you use the **required structures**: file reading, loop, selection, list/array, subprogram, validation?
- **Input validation:** does it reject bad input and ask again?
- **Testing:** did you design test data (normal, boundary, erroneous), with expected results, and say what happened?
- **Readability:** comments, good names, indentation, no repeated blocks that should be a function.
- For each lost mark, label it: **K** (didn't know the construct or syntax), **T** (misread the task or format), **L** (logic error), **C** (careless typo), **R** (ran out of time).
- Write **fixes** next to the code: the line you would change, and what the correct line is. Re-type the corrected version rather than only reading it.
- Compare the **efficiency**: if the sample uses a loop and you wrote the same line five times, practise turning repetition into a loop.

## Quick-fire revision

- Count-controlled loop: `for i in range(1, 11):` runs i = 1 to 10 (the end value is not included).
- Condition-controlled loop: `while x != 0:`; make sure something inside the loop changes x.
- Reading numbers from a file: `n = int(line.strip())`; CSV: `parts = line.strip().split(",")`.
- Running total: `total = 0` before the loop; `total = total + value` inside; average = `total / count`.
- Maximum: `highest = values[0]`; `if v > highest: highest = v`.
- Linear search: loop through; if item matches, set `found = True` and break.
- Validation loop: `while not valid:` ask again; or `while n < 1 or n > 10:`.
- Modulus `%` gives the remainder: `n % 2 == 0` tests for even; integer division `//` gives the whole part.
- String handling: `len`, slicing, `.upper()`, `.lower()`, concatenation with `+`, convert numbers with `str()` for output.
- Functions: `def area(width, height): return width * height`; call with `a = area(3, 4)`.
- Local variables exist only inside the function; global variables are visible everywhere (avoid changing them inside functions).
- Common errors: missing colon, wrong indentation, `=` instead of `==`, forgetting to convert `input()` text to a number, off-by-one in `range`.
- Test plan columns: test data, type (normal/boundary/erroneous), expected result, actual result.
- Always read the **last line** of an error message first.
