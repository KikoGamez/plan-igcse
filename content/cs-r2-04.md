## Exam format reminder

- Paper 2 was **75 marks, 1 h 45**, 50% of the IGCSE: algorithms, programming, databases and logic, all compulsory, ending with a **longer scenario question** that asks you to write a program (pseudocode or a high-level language).
- Mark schemes for code use **mark points**: e.g. *declaration*, *loop*, *input*, *validation*, *running total*, *condition*, *output*. Any **correct solution** scores, not just the one in the scheme, as long as it works.
- Programming marks are often lost for **small slips**: missing initialisation, wrong loop limits, output inside the loop.

### Scenario practice question

*A leisure centre records the number of visitors each day for one week. The array `Days[1:7]` already holds the day names ("Monday" to "Sunday"). The array `Visitors[1:7]` is empty. Write a program that: inputs the number of visitors for each day, **rejecting any value that is not between 0 and 500** and asking again; calculates and outputs the **total** and the **average**; outputs the **name of the busiest day**. [10]*

Write it before looking below. **Model answer:**

```
DECLARE Visitors : ARRAY[1:7] OF INTEGER
Total ← 0
Busiest ← 1
FOR I ← 1 TO 7
   REPEAT
      OUTPUT "Enter visitors for ", Days[I]
      INPUT Visitors[I]
   UNTIL Visitors[I] >= 0 AND Visitors[I] <= 500
   Total ← Total + Visitors[I]
   IF Visitors[I] > Visitors[Busiest] THEN
      Busiest ← I
   ENDIF
NEXT I
Average ← Total / 7
OUTPUT "Total: ", Total
OUTPUT "Average: ", Average
OUTPUT "Busiest day: ", Days[Busiest]
```

**Mark points:** loop through 7 days [1]; input stored in array element [1]; validation loop with the right range [2]; running total [1]; initialise total [1]; track the largest (or its index) [2]; average calculated [1]; outputs of total, average and busiest day name, outside the loop [1].

If you lost marks, ask: Did I **initialise**? Did I put the **output after** the loop? Did I output the **name** (`Days[Busiest]`) rather than the number?

## Exam technique for this paper

- For a long question: **underline** every input, rule and output in the scenario; **tick them off** as you code them.
- **Plan in the margin**: variables, loops, decisions. Writing is faster with a plan.
- **Use the names** given in the question.
- If you cannot finish, write **partial code**: declaration, loop, input, one decision: these are marks.
- **Check** by tracing with 2 test values.
- On **SQL** and **logic** questions, the common errors are keyword order, missing quotes, and missing rows or intermediate columns.

## Quick-fire revision

- Initialise totals and counters **before** the loop.
- Output a total or average **after** the loop.
- Validation loop: `REPEAT INPUT … UNTIL (valid condition)`.
- Max: start with the **first item**, not 0.
- Array declaration: `DECLARE Name : ARRAY[1:n] OF TYPE`.
- 2D array: `Grid[row, column]`, nested FOR loops.
- Functions need a **RETURN**; call them within an expression.
- File reading: **OPEN**, loop until **EOF**, **READ**, **CLOSE**.
- Strings: `LENGTH`, `SUBSTRING`, `UCASE`, `LCASE`; `&` joins.
- SQL: `SELECT * FROM Table WHERE … ORDER BY … DESC;` and `COUNT(*)`, `SUM(field)`.
- Truth table: write the **intermediate gate columns**.
- NOT is a small circle on the output of a gate symbol.
- Test data: normal, abnormal, extreme, boundary. Always give the **expected result**.
- Trace table: **one row per change**.
